# note販売 記事制作チーム

note記事を作って販売するための、役割が分かれた5つの専門エージェントで構成されています。エージェント定義本体は `.claude/agents/` にあります。

## エージェント一覧と役割

| # | エージェント名 | 役割 | 使わない仕事 |
|---|---|---|---|
| 1 | `note-researcher` | テーマ・読者のリサーチと分析 | 構成作成、執筆、校正 |
| 2 | `note-structurer` | 見出し構成・章立て・無料/有料の区切り設計 | 本文執筆、リサーチ |
| 3 | `note-writer` | 構成に沿った本文の執筆 | 構成変更、販売ページ執筆 |
| 4 | `note-copywriter` | 販売ページ（紹介文・レター）の執筆 | 本文の編集、構成変更 |
| 5 | `note-editor` | 誤字脱字・言い過ぎ表現のチェックと修正（最終工程） | 構成・内容の大幅変更 |

## 作業フロー

```
テーマを決める
   ↓
① note-researcher   → note販売/research/<案件ID>_research.md
   ↓
② note-structurer   → note販売/outlines/<案件ID>_outline.md
   ↓
③ note-writer        → note販売/drafts/<案件ID>_タイトル.md
                        note販売/drafts/<案件ID>_タイトル_meta.md
   ↓
④ note-copywriter    → note販売/sales_pages/<案件ID>_sales_page.md
   ↓
⑤ note-editor         → 上記ファイルを直接修正 + note販売/reviewed/<案件ID>_review_report.md
   ↓
公開・販売
```

各エージェントは「案件ID」（例: `01`, `02`, `03_投資リスク管理` のような連番+スラッグ）を通じてファイルを受け渡します。案件IDが未指定の場合、リサーチ担当が既存ファイルの連番の続きを採番します。

## ディレクトリ構成

- `research/` … リサーチメモ（①の成果物）
- `outlines/` … 構成案（②の成果物）
- `drafts/` … 記事本文・メタ情報（③の成果物）
- `sales_pages/` … 販売ページ文章（④の成果物）
- `reviewed/` … 校正レポート（⑤の成果物）

## 呼び出し方の例

「投資・株をテーマにnote記事を作りたい」のように伝えると、①→⑤の順にエージェントを呼び出して一気通貫で仕上げます。特定の工程だけをやり直したい場合（例：「03の構成だけ作り直して」）は、該当するエージェント名を指定してください。
