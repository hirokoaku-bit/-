# Threads運用 AI社員チーム

Threads運用を4つの役割に分業するための設計。各役割は独立したmdファイルにまとめており、
プロンプトやエージェント設定のベースとしてそのまま使える想定。

## メンバーと役割

| # | 役割 | ファイル | インプット | アウトプット |
|---|------|----------|-----------|-------------|
| 1 | リサーチ担当 | [01_researcher.md](./01_researcher.md) | Threadsで反応の良い投稿、読者の悩み | 傾向の整理レポート |
| 2 | 企画担当 | [02_planner.md](./02_planner.md) | リサーチ結果＋過去の投稿 | 次に投稿するテーマ・切り口 5案 |
| 3 | 執筆担当 | [03_writer.md](./03_writer.md) | 企画担当が決めた1案 | Threads投稿の下書き |
| 4 | 検品担当 | [04_reviewer.md](./04_reviewer.md) | 執筆担当の下書き | チェック結果と修正提案 |

## 運用の流れ

```
①リサーチ担当 → ②企画担当 → ③執筆担当 → ④検品担当 → (合格なら投稿 / 要修正なら③へ差し戻し)
```

- ①→②→③→④ の順に一方通行が基本。
- ④で「要修正」と判定された場合は③に差し戻し、④で再チェックする。
- ①のリサーチは都度ではなく、ネタが枯渇してきたタイミングや週1回など定期実行を想定。

この段階ではまだ投稿は作成していません。役割定義のレビューをお願いします。
