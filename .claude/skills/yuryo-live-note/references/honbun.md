# 有料パート本文を書く

**型の正は `honnin-kata.md` の工程3〜6。** この文書はその実行手順。食い違ったら honnin-kata を優先する。

無料パートの書き方は `muryo-part.md`（有料パートを書き終えてから書く）。

## 役割

**お金を払った人に、払ってよかったと思わせる。**

販売はもう終わっている。ここから先は満足だけを作る。

**うまく書こうとするほど、売れなくなる。** 買う人が見ているのは文章の巧さではない。

## 材料を先に出す（AIに白紙から書かせない）

本人の型の中核。**自分で材料を出す → AIに整えてもらう。** 順番を逆にすると中身が薄くなる。

### 線引き

AIに任せていいのは**整える仕事**（並べ替え、言い回しの統一、見出し案、誤字チェック、長い文を割る）。

本人に書いてもらうのは**判断が要る仕事**。次の4つ。

- 詰まった場所と、その直し方
- なぜその方法を選んだのかの理由
- やってみて分かった、注意しておくこと
- 読む人への呼びかけ、率直な感想

**有料noteの価値は後者に宿る。** ここが空のまま本文を書くと、「大切なのは継続することです」レベルの文章になる。

### 材料が足りないとき

章ごとに、**本人のメモ**（手順・つまずいた場所・具体的な数字・実際にあった失敗）が揃っているか確認する。

ここが空の章は、**そこで止めて本人に聞く**。憶測で埋めない。一般論で埋めない。

## 章の順番

**自分が理解した順ではなく、読む人の作業順に並べる。**

- 1章に2つ入れない
- 順番が合っているかは、上から実行できるかで確かめる

## 1章の型（5ブロックの穴埋め）

1. **なぜこれをやるのか** — この章を飛ばすとどうなるか（3〜4行で十分）
2. **手順** — 上から順にやれば終わる形（**全体の半分くらい。いちばん厚くする**）
3. **具体例** — 実際の画面、実際の文面、実際の数字
4. **つまずく場所** — ここで止まる人が多い、という予告と対処
5. **この章のゴール** — 何が終わっていればOKか（2行で終わる）

章の最後は太字で1行締める。

```
**今日のゴール：紙に3行書く。読む人／できるようになること／無料と有料の境界。**
```

**全章を同じ順にしない。** 2〜3章は要素の順を入れ替えるか、1つ落とす（AI感を消すため）。

## 手順の書き方

**画面に出ている言葉を、そのまま使う。言い換えない。**

- 悪い：設定画面を開いて、必要な項目を入力します
- 良い：右上の歯車マークを押して、「アカウント設定」を選びます

読む人は画面を見ながら読んでいる。書いてある言葉と画面の言葉が違うと、そこで止まる。

スクリーンショットを貼れるところは貼る。**文章5行より画像1枚のほうが伝わる。**

プロンプト・テンプレは**全文**書き出す。「ここで使います」の要約で済ませない。

## 買った直後の1画面

有料ラインを越えた最初の1画面で勝負が決まる。

1. **買ってくれたお礼を1行**（重くしない）
2. **前置きなしで、いちばん価値のあるものを1つ渡す**（テンプレ全文・基準の数字・結論）
3. 渡したものの使い方を2〜3行

やらないこと：

- 「ここからが本番です」で始めて、また前置きを始める
- 買った人への長い挨拶
- 有料パートの目次をもう一度並べる

**判定：** 最初の1画面をスクロールし終えたとき、もう元が取れていると感じるか。

## 質問を先に潰す（書き終えたあと）

読む人になったつもりで質問を5つ書き出す。

「この方法、無料のプランでもできますか」「Macじゃないとダメですか」「途中でやめたらどうなりますか」

本文で答えていないものを、**該当する章の中に**1〜2行足す。Q&A欄にまとめるより読まれる。

## 締め

**長いまとめは要らない。「今日やること」を1つだけ置く。**

読み終わった人はたいてい満足してそのまま何もしない。1つだけ具体的な行動が書いてあると、そこだけはやってくれる。

そのあと、profile.md の「5. 記事の最後に何をすすめるか」に従う。順番は固定。

1. 読んでくれたお礼（1行）
2. 今日やること（1つ）
3. **1人だと止まりやすい場所の提示**（honnin-kata の5か所の型。自分の記事の内容に合わせて3〜5個）
4. profile.md に書かれた誘導先へ（説明文があれば語順を変えずそのまま置く）

**誘導先が「なし」なら、1と2だけで締める。** 行き先の無い「止まりやすい場所」の一覧は置かない。

やらないこと：

- 「いかがでしたか」で締める
- 説教で締める（「あとは行動あるのみです」）
- 価値を渡す前に誘導する

## 文体ルール

### 書く前に profile.md から引くもの

| 引くもの | どこ | 効かせ方 |
|---|---|---|
| 読者への呼びかけ方 | 3-2. 文章の好み | 「あなた」「みなさん」を記事全体で統一する。「呼びかけない」なら二人称を使わない |
| 絵文字を使うか | 3-2. 文章の好み | 「使わない」なら本文にも見出しにも入れない |
| 太字は多めか少なめか | 3-2. 文章の好み | 「少なめ」なら1つの見出しにつき太字は1〜2か所まで |
| 寄せたい書き手 | 3-2. 文章の好み | 空欄でなければ、その人の文章を検索して読み、リズムだけ寄せる。内容は真似しない |
| 書きたくない話題 | 6-4. 使ってはいけない表現 | 本文にも画像にも出さない |
| **口ぐせ・よく使う言い回し** | 9. あなたらしさを深める | **章に1〜2回、自然に混ぜる。** 連発しない。ここがAI感を消す一番の要素 |
| よく使うたとえ | 9. あなたらしさを深める | 説明が難しい場面で使う。**記事全体で同じたとえ**にそろえる |
| 今でも苦手なこと | 9. あなたらしさを深める | 逃げ道フレーズに使う（「僕も今でもここは苦手で」）。完璧な人に見せない |

**空欄の項目は無視してよい。** 書いてあるものだけ守る。

### メイン語尾

- 〜なんです。／〜なんですよね。／〜なんですよ。／〜なんですけど、／〜だったりするんです。

### 補助語尾

- 〜でOKです。／〜で大丈夫です。／〜かなと思います。／〜です。

### 同一語尾3連続禁止

## 見出しの形

H3は**疑問形が主体**。

- 有料ラインは、どこで切るのか
- 任せていいのは、どこまでか
- 質問は、来る前に潰せますか

失敗談と結論だけ断定形にする。

- もったいぶった無料パートは、最後まで読まれませんでした

## 段落ルール

- 1段落2〜3行
- 長文禁止
- 改行多め
- 同じ長さの段落連続禁止

## 内容ルール

### 数値は現実的な目安のみ

OK：通過率30%未満／1記事60分目安／実績3件で単価相談
NG：誰でも月100万／絶対成功／一瞬で変わる

### 事実の裏取りは無料noteより厳しくやる

- 料金・上限・仕様・制度は**一次情報で確認**する
- 変わりやすいものは「◯年◯月時点」を添える
- 裏が取れないものは「僕の場合は」に変えるか、書かない

### 読者を詰まらせない

各章に最低1つ入れる。

- 全部やらなくて大丈夫です
- まずここだけ見てください
- 迷うならこれでOKです

## 文字数（上限で管理する）

`profile.md` の「6-2. 記事の長さ」の**1章あたりの上限**に従う。有料パート全体の目安も同じ欄にある。**下限で管理しない。** 下限だと足りない気がして書き足し続ける。

上限を超えたら、足すのではなく**どれを削るかを考える**。そのほうが記事は良くなる。

材料が足りなくて上限に届かない章は、水増しせず短いまま出す。**中身が足りていれば、短いことは欠点にならない。**

### 文字数の数え方

Pythonで空白・改行を除去してから数える。

```python
import re
len(re.sub(r"\s", "", text))
```

`wc -m` は使わない。

## 画像

**有料パートは、手順の章に厚く入れる。**

- 手順の章：画面のスクリーンショットを優先。文章5行より画像1枚
- 説明の章：500字に1枚が目安
- 本文中は `［図：〜］` のマーカーで置き、あとで差し替える
- **画像を作らずに入稿するときは、マーカーをすべて削除する。** 残すと入稿前の検査で止まる

## 出力形式

- 章タイトルは `## `（H2）、小見出しは `### `（H3）
- 強調は太字（`**〜**`）のみ。箇条書き記号は `-`
- 構成の章立て・見出しを勝手に変えない。変えたほうがいい場合は本文の後に提案として添える
- 有料ラインの位置に `<!-- ここから有料 -->` を1行入れる（入稿ツールが自動で取り除く）

### URLの書き方（重要）

読者に渡したいURLは、**文章と同じ行に生のURLで置く**。

```
アカウントはこちらです https://www.instagram.com/（あなたのID）
```

URLだけの行にもしない（noteがリンクカードに変えるため）。

## AI感の正体は「型の均一」（書き終えたら必ず1周見る）

- **章の型を毎回同じにしない**（2〜3章は順番を入れ替えるか要素を1つ落とす）
- **語尾を散らす**（「〜なんですよね」が5回以上なら多い）
- **言い直しを残す**（「……と書いておいてなんですが」を記事全体で2〜3回）
- **失敗談を数字と動作まで降ろす**（「探し回りました」→「フォルダの中を10分くらい探しました」）
- **段落の長さを不均一にする**

## 出力前チェック

- 本人の材料から書いたか（一般論で埋めていないか）
- 買った直後の1画面で、前置きなしに現物を渡しているか
- 各章が5ブロックで埋まっているか
- 手順が章の半分くらいの厚みか
- 画面の言葉をそのまま使っているか
- プロンプト・テンプレが全文で書かれているか
- 各章に「僕」が最低1回出てくるか
- 各章に逃げ道があるか
- 各章末に「今日のゴール」があるか
- 質問5つを潰したか
- 締めが「今日やること1つ」になっているか（長いまとめになっていないか）
- 章ごとの上限を超えていないか
- 数字・料金・仕様の裏を取ったか。時点表記を添えたか

### 使わない言葉

- 装飾のアスタリスク（`*`囲み・斜体）（強調の太字`**〜**`はOK）
- 「だから」（→「なので」）
- 「〜です。」の3連続
- 「以下の〜」「上記の〜」「本記事では」などの教材用語
- 「重要なのは〜」「ポイントは〜」系の上から目線
- 1段落4行以上
- 煽り（今だけ／限定／絶対／必ず／誰でも／保証）

## 最終ルール

**60点で出す。** noteは公開後に本文を直せる。完璧を目指して止まるより、出して反応を見たほうが速く良くなる。

ここでの60点は「完璧主義で止まるな」という意味であって、品質を下げていいという意味ではない。
