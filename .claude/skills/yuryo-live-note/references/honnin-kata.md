# 有料noteの型（7工程）

**この文書が、有料noteの型の正。** 他の references と食い違ったら、こちらを優先する。

出典：きっしー（@ki__aikatuyou）が、自分で有料noteを書いて売るなかで言語化した7工程。

一般論ではなく、実際に書いて売った人が言語化したもの。**一般的なライティング論で上書きしない。**

---

## 工程1｜書き始める前に、3つだけ決める

- 読む人（1人に絞る）
- 読み終わった人ができるようになること
- **どこまで無料で、どこから有料にするか**

3つ目を先に決める。書きながら決めない。境界が決まっていないと、無料パートも有料パートも役割が定まらない。

**今日のゴール型：** 紙に3行書く。

---

## 工程2｜無料パートは「買う理由」を作る場所

### 置くのはこの4つだけ

1. **悩みの言語化** — 読む人が言葉にできていない状態を、代わりに言葉にする
2. **全体像** — これから何をするのかの地図。工程がいくつあるか
3. **結論** — 答えそのもの。**隠さない**
4. **この先の予告** — 有料パートで何が手に入るか。目次を見せてしまってもいい

**1がいちばん大事。** ここで「自分のことだ」と思ってもらえないと、以降は読まれない。

### 有料ラインの切り位置

**「分かった」の直後、「やってみよう」の直前。**

読んだ人の頭が「なるほど、そうすればいいのか」で止まっている場所。そこから先の「で、具体的にどうやるのか」が有料パート。

**判定のしかた：** 無料パートだけを読み返して、読み終わったときに「で、どうやるの？」と自分で思えたら、そこが切り位置。すっきり終わってしまったら、切る位置が後ろすぎる。

### 実際にあった失敗（書き方ルールの根拠）

もったいぶって核心を避け、「詳しくは本編で」「ここから先が本題です」と何度も書いた結果、**有料ラインまでたどり着く人が少なかった**。

> 何も書いていない文章を、人は最後まで読まない。もったいぶった文章は、読む人にとっては中身のない文章と同じ。

### やりがちな失敗2つ

- 全部隠す
- **手順まで全部出してしまう**（答えは出していい。手順を出すと買う理由が消える）

### 書く順番

**無料パートは、最後に書いてもいい。** 有料パートを書き終えてからのほうが、何を見せるべきかが見える。

---

## 工程3｜有料パートは「順番」で価値が決まる

払われているのは情報量ではなく順番。

**自分が理解した順ではなく、読む人の作業順に並べる。**

- 1章に2つ入れない
- 順番が合っているかは、上から実行できるかで確かめる

---

## 工程4｜1章は5ブロックの穴埋め

1. **なぜこれをやるのか** — この章を飛ばすとどうなるか（3〜4行で十分）
2. **手順** — 上から順にやれば終わる形（**全体の半分くらい。いちばん厚くする**）
3. **具体例** — 実際の画面、実際の文面、実際の数字
4. **つまずく場所** — ここで止まる人が多い、という予告と対処
5. **この章のゴール** — 何が終わっていればOKか（2行で終わる）

### 手順の書き方

**画面に出ている言葉を、そのまま使う。言い換えない。**

- 悪い：設定画面を開いて、必要な項目を入力します
- 良い：右上の歯車マークを押して、「アカウント設定」を選びます

読む人は画面を見ながら読んでいる。書いてある言葉と画面の言葉が違うと、そこで止まる。

スクリーンショットを貼れるところは貼る。文章5行より画像1枚のほうが伝わることが多い。

### 心構え

**うまく書こうとするほど、売れなくなる。** 買う人が見ているのは文章の巧さではない。

---

## 工程5｜AIは材料を出してから使う

**薄くなるのは、書かせる順番が逆だから。** 白紙からAIに書かせない。

### 正しい順番

**自分で材料を出す → AIに整えてもらう。**

材料＝自分しか持っていない情報。実際にやってみた手順／うまくいかなかった場面／何を試して何が効いたか／読む人が引っかかりそうな場所。箇条書きでいい。雑な日本語でいい。

### 線引き

AIに任せていいのは**整える仕事**（並べ替え、言い回しの統一、見出し案、誤字チェック、長い文を割る）。

自分で書くのは**判断が要る仕事**。具体的には次の4つで、ここが有料noteの価値になる。

- 詰まった場所と、その直し方
- なぜその方法を選んだのかの理由
- やってみて分かった、注意しておくこと
- 読む人への呼びかけ、率直な感想

> 前者は他の人が書いても同じものになる。後者は自分にしか書けない。

### 実際にあった失敗

章タイトルだけ渡して本文を書かせたら、「大切なのは継続することです」「自分に合った方法を見つけましょう」が出てきた。読みやすくて、中身がなかった。しかも読みやすいので直す気になりにくい。結局まるごと捨てた。

## 工程6｜期待を合わせる仕上げ

低評価の原因は、中身の薄さより先に**期待のズレ**。仕上げでやるのは「中身を厚くする」ではなく「期待を合わせる」。

### 冒頭に並べて書く（いちばん効く）

**「この記事で得られること」と「この記事では扱わないこと」を、並べて書く。**

扱わないことを書くと売れなくなりそうに見えるが、実際は逆。輪郭がはっきりして、必要な人に届く。

```
**この記事で得られること**
- （具体的に）
- （具体的に）

**この記事では扱わないこと**
- （別記事で扱うもの）
- （範囲外のもの）
```

### 質問を先に潰す

書き終わったあと、読む人になったつもりで質問を5つ書き出す。本文で答えていないものを、**該当する章の中に**1〜2行足す。Q&A欄にまとめるより読まれる。

### 最後に置くもの

**長いまとめは要らない。「今日やること」を1つだけ置く。**

読み終わった人はたいてい満足してそのまま何もしない。1つだけ具体的な行動が書いてあると、そこだけはやってくれる。やってくれた人は、次も買う。

### 公開前に見るのは3項目だけ

得られること／扱わないこと／今日やること。

### noteの返金の仕組み（2026年8月時点・本人が確認したもの）

- 購入者が返金を申請できるのは、**購入から24時間以内**
- 申請できるのは、書いた側が「返金申請を受け付ける」設定にしている記事のみ
- **何も変更しなければ「受け付ける」状態で公開される**（初期設定）
- 販売開始後に設定を変えても、変更前に買った人からの申請は受け付けられる
- ゲスト購入（会員登録なし）は返金の対象外

受け付けない設定にすると、購入者側に「返金不可」と表示される。初めて買う人には引っかかることもある。

**どちらが良いかは考え方次第。ただし設定を知らないまま公開しない。** 公開設定の画面で1回確認する。

> 仕様は変わる。販売前に必ず最新を確認し、確認した時点を記事に添える。

## 工程7｜終わりを先に決める

### 完成の定義（書き始める前に決める）

- **章の数**（増やさない）
- **1章あたりの文字数の上限**

**上限を決める。下限にしない。** 下限だと足りない気がして書き足し続ける。上限なら「どれを削るか」を考えることになり、そのほうが記事は良くなる。

### 7日の割り振り

- 1日目：3つを決める（30分）
- 2日目：目次を確定。章を作業順に並べ替える（1時間）
- 3日目：1章目
- 4日目：2〜3章目
- 5日目：残りの章
- **6日目：無料パートを書く。冒頭の「得られること／扱わないこと」を書く**
- 7日目：通しで1回読んで、公開設定を確認して出す

書けない日は締め切りを動かさず、**その章を短くする**。1,500字の予定を800字に。中身が足りていれば短いことは欠点にならない。

### 心構え

**60点で出す。** noteは公開後に本文を直せる。1人で悩むより、出して反応を見たほうが速く良くなる。

## 1人だと止まりやすい5か所（締めの誘導の根拠）

- **絞る**（工程1）— 自分では絞ったつもりでも、他人が読むと誰向けか分からない
- **切る**（工程2）— 自分は全部知っているので、無料と有料の境目が見えない
- **順番**（工程3）— 自分の記事は、どの順番でも読めてしまう
- **材料**（工程5）— 材料の出し方が浅いと、指示を工夫しても変わらない
- **締め切り**（工程7）— 自分で決めた締め切りは、自分で延ばせる

共通するのは、**どれも自分1人では判断がつかない**という点。文章力の問題ではない。

締めの誘導は、この5か所を「一緒に潰す場」として、profile.md の誘導先（セミナー・公式LINE・個別相談など）につなぐ。売り込みではなく、詰まる場所の提示で引く。

**誘導先が無いときは、この一覧を記事に置かない。**

## 見出しの形（実物から）

H3は**疑問形が主体**。

- 書けないのは、文章がヘタだからでしょうか
- 有料ラインは、どこで切るのか
- 任せていいのは、どこまでか
- 質問は、来る前に潰せますか

断定の見出しは、失敗談と結論に使う。

- もったいぶった無料パートは、最後まで読まれませんでした
- 1章の中身は、5つのブロックでできています

## 図のマーカー

本文中に `［図：〜］` の形で置き、あとで画像に差し替える。

```
［図：有料ラインを引く位置］
```

## 各章の締め

章の最後に、太字で1行置く。

```
**今日のゴール：紙に3行書く。読む人／できるようになること／無料と有料の境界。**
```
