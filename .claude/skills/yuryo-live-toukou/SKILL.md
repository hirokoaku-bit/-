# yuryo-live-toukou — noteに下書きを入れる

`~/yuryo-kit-live/note-draft` のツールで、記事フォルダを note.com の下書きにする工程。

**公開は絶対にしない。** このツールは下書き保存で止まる作りになっている。公開ボタンはユーザーが自分で押す。

## 前提

- 入稿するものが `articles/<slug>/` に揃っていること
  - `article.md`（frontmatter に `title` と `tags`）
  - `images/*.png`（本文中に `![説明](./images/xxx.png)` で参照されている）
- note.com にログイン済みであること（`storage/note-auth.json` がある）

## 手順

### 1. 環境を確認する

```bash
cd ~/yuryo-kit-live/note-draft
npm run doctor
```

「保存済みログイン状態 あり」が出ればOK。出なければ**ここで止まってユーザーに頼む**。

```bash
cd ~/yuryo-kit-live/note-draft && npm run login
```

> **ID・パスワードは代わりに入力しない。** ブラウザが開くので、ユーザー自身がログインする。

### 2. 入稿せずに下見する（dry-run）

```bash
cd ~/yuryo-kit-live/note-draft
npm run dry-run -- articles/<slug>
```

noteには一切アクセスしない。タイトル・文字数・画像枚数・タグが想定どおりか確認する。

### 3. 下書きを作る

```bash
cd ~/yuryo-kit-live/note-draft
npm run draft -- articles/<slug> --headed
```

`--headed` でブラウザを表示する。ブラウザ操作なので数分かかる。

外部への書き込みなので、**ユーザーの指示がない限り勝手に実行しない**。

### 4. 中身を検証する（ここを飛ばさない）

コマンドが成功しても、中身が正しいとは限らない。**必ず次の2つを見る。**

**1. 実行時の出力を見る**（いちばん早い）

`draft` の実行結果に、そのまま次が出る。

- `imagesInline` … 本文中の正しい位置に入った画像の枚数
- `imagesLeftOver` … 位置に置けず末尾に回った枚数。**0以外なら要調査**
- `body-image-insert-failed` … 挿入に失敗した画像
- `images-appended-at-end` … 末尾送りが起きた警告

あとから見たいときは、ログファイルを読む。**ファイル名は日付つきではなく1本**で、実行のたびに追記される。

```bash
cd ~/yuryo-kit-live/note-draft
tail -40 logs/note-auto-draft.log
```

**2. 入った中身をテキストで確認する**（ここを飛ばさない）

下書きURLを渡すと、本文の並びと画像の位置をそのまま出してくれる。表・箇条書き・画像位置の確認はこれが一番速い。

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/verify-full.mjs "<下書きURL>"
```

見るところ：

- 画像が**本文の該当位置**にあるか（末尾に固まっていないか）
- 表が「**項目**：説明」の箇条書きになっているか（`|` が残っていないか）
- `**` や `` ` `` がそのまま文字として出ていないか
- 番号付きリストの項目数が0であること（見出しの数字がリストに化けていないか）

**3. 画面を目で見る**

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/verify-draft.mjs "<下書きURL>"
```

`screenshots/verify-top.png` に記事の上部が保存されるので Read で開く。
サムネイル・タイトル・見出し・太字・引用がそろっているかを見る。

> `draft` 実行時にも `screenshots/` にスクショが残るが、**画面に見えている範囲だけ**（1280×720）。
> 記事の下のほうを見たいときは、上の `verify-full.mjs` のテキストで確認する。

## 記法の対応状況（2026-08-06に全部通した）

| 記法 | 結果 |
|---|---|
| 大見出し・小見出し（`##` / `###`） | そのまま変換される |
| 箇条書き・番号リスト | 変換される。リストから段落に戻るのも正常 |
| 引用（`>`） | 引用ブロックになる |
| 太字（`**`） | 行の途中も**行末も**変換される |
| コードブロック（``` の囲み） | 中身入りのコードブロックになる |
| インラインコード（`` ` ``） | **noteに変換規則が無い。** バッククォートを外してプレーン表示にしている |
| 表（`\| 項目 \| 説明 \|`） | **noteに表の機能が無い。** 箇条書き「**項目**：説明」に変換して入れる。ヘッダ行と区切り行は落とす。3列以上は2列目以降を「 / 」でつなぐ |
| 区切り線（`---`） | **落とされる。** `articleParser.ts` が「noteに無いので落とす」実装。noteでは見出しで章が分かれるので、記事としては問題ない |
| 画像 | 本文の該当位置に入る |
| リンク付き画像（`[![alt](画像)](URL)`） | **使えない。** noteにその機能がなく、`[` と `](https://…` が文字として本文に残る。画像は普通に置き、リンクは直前の行のテキストリンクにする |
| `__` を含む語の太字（`**@ki__aikatuyou**`） | **使えない。** noteが `__` を強調記法と解釈してアンダースコアが消え、閉じの `**` だけ残る（`@kiaikatuyou**` になる）。太字にせずそのまま書く |
| URLだけの行 | noteがリンクカードに変換する。変換の完了を待つ処理を入れてあるが、カードにしたくないときは文章と同じ行にURLを置く |

インラインコードだけは見た目が普通の文字になる。強調したい語は太字か「かぎかっこ」にしておくと意図どおりになる。

### 5. 報告する

- 下書きURL
- 画像が正しい位置に入ったか（枚数つき）
- 公開していないこと
- **入稿が終わると、道具が「ここから先は、あなたの手で設定してください」と4行出す。** その内容をそのまま相手に伝える（暗記して言い直さない）
  1. 有料ラインの位置（どの見出しの直前か）
  2. 販売価格
  3. 返金申請の設定
  4. タグ（noteは自動でタグを入れられないので、下書き画面で貼ってもらう）
- 画面に「空欄です」と出た項目は、`profile.md` のどこを埋めればよいかも一緒に伝える
- 残っている手作業があれば明記する

## ツールが壊れたときの直し方

noteは画面デザインを変えるので、ときどき動かなくなる。慌てて何度も実行しない。

| 症状 | 見るファイル |
|---|---|
| ボタンや入力欄が見つからない | `src/selectors.ts`（触る場所の指定が集約されている） |
| 本文の見出し・箇条書きが崩れる | `src/noteEditorAdapter.ts` の `fillBody` |
| 画像の位置がおかしい | `src/noteEditorAdapter.ts` の `fillBody` と `insertImageAtCursor` |
| サムネイルが入らない | `src/noteEditorAdapter.ts` の `setThumbnail` |

直したら**必ず**この順で確認する。

```bash
cd ~/yuryo-kit-live/note-draft && npm run typecheck && npm test
```

### noteエディタの実測ルール（直すときの前提）

ここを外すと崩れる。全部ハマった箇所。

- 段落の中で Enter を1回押すと**改行になるだけで、ブロックは変わらない**
- 新しいブロックにするには、段落やリストからは Enter 2回、見出しの直後と画像の直後は1回
- 見出し（`##`）・箇条書き（`- `）・コードブロック（```）は、**本当の空ブロックの先頭**で打ったときだけ変換される
- 太字などのインライン記法は、**閉じ記号の次の文字を打った瞬間**に変換される。閉じ記号が行末だと変換されないので、末尾に半角スペースを1つ打って変換させる
- コードブロックの**中では** Enter 1回がブロック内の改行、2回で外へ抜ける
- なので、コードブロックの中に**空行をそのまま置けない**。空行はEnterが2回続いた形になり、そこで抜けてしまう。空行では**半角スペースを1つ打って「文字のある行」にする**
- `page.keyboard.insertText('\n')` は**効かない**。noteのエディタが無視して全部1行につながる。改行はEnterで打つ
- 画像は「空のブロックに出る＋ボタン」から入れる。リストの中からは Enter 2回で抜けてから入れる

### 2026-08-06に直したこと

**1. 画像が本文の位置を無視して末尾にまとめて入る**

`fillBody` が本文を打ちながら、`![](…)` の行に来たらその場で入れる方式に変更。パスで突き合わせるので順番がずれない。末尾にまとめる旧処理は保険として残し、**置けなかった分だけ**回る（ログの `imagesLeftOver` と `images-appended-at-end` で分かる）。

**2. コードブロックの中身が消えて黒い空箱になる**

``` を本当の空ブロックの先頭に置けていなかったのが原因。移動のEnter回数を直し、中身は Enter 1回区切りで打ち、最後に Enter 2回で抜けるようにした。

**3. 行末で終わる太字とインラインコードがそのまま出る**

`typeInline` を追加。行末が `**` なら半角スペースを1つ足して変換させ、インラインコードのバッククォートは外す。


### 2026-08-26に直したこと

**コードブロックに空行があると、そこで抜けて以降が普通の段落になる**

プロンプトを載せる記事で発覚。`case 'code'` が空行のとき文字を打たずEnterだけ押していたため、Enterが2回続いてブロックから抜けていた。空行では半角スペースを1つ打つように変更（`line.lines[i] || ' '`）。

先に `insertText('\n')` を試したが、こちらは**改行そのものが入らず全部1行につながる**ので使えない。改行はEnterで打つこと。


### 2026-08-30に直したこと

**URLだけの行の次のブロックが、まるごと消える**

noteはURLだけの行をリンクカードに変換する。その変換の途中で次のブロックへ移ると、ブロックごと消えて空段落だけが残っていた。
`case 'paragraph'` でURLだけの行を打ったあと2.5秒待つようにした。


### 2026-08-31に直したこと

**表がそのまま文字として入っていた**

`| 項目 | 説明 |` が変換されず、縦棒つきの本文としてnoteに入っていた（説明書は「箇条書きに変わる」と書いてあり、実装と食い違っていた）。
`articleParser.ts` に表の変換を実装し、上の表のとおり「**項目**：説明」の箇条書きになるようにした。

2026-09-01に**実機で入稿して確認済み**。noteの下書きに「**図解**：手順や比較を見せる」の形で入り、`|` は残らない。


## やらないこと

- **公開しない。** 下書き保存で止める。公開はユーザーが画面で確認して手で行う
- **下書きを消さない。** 作り直しで不要になった下書きが出ても、削除はユーザーに頼む
- **同じコマンドを繰り返さない。** 失敗したら原因を特定して、次の手をユーザーに確認する
- **ログイン情報を入力しない。** ログインが切れていたらユーザーに頼む
