# サムネイル（見出し画像）の型

note記事の一番上に出る「見出し画像」の見た目。

## いちばん大事な前提

**挿入図解とサムネイルは、作り方が違う。**

| | 挿入図解（`zukai-style.md`） | サムネイル（このファイル） |
|---|---|---|
| 目的 | 読ませる・理解させる | 一覧で目を止めさせる |
| 密度 | 余白をとってすっきり | **びっしり埋める** |
| 要素の数 | 1つの型だけ | **タイトル＋帯＋イラスト＋工程＋バッジ＋特徴リスト** |
| 文字 | 落ち着いた太さ | **画面を占領する極太** |

ただし**やり過ぎない**。目指すのは「クリーンで整理された情報デザイン」であって、
金色の装飾や3Dの縁取り文字でギラギラさせることではない。

## 共通ルール

| 項目 | 指定 |
|---|---|
| 比率 | 16:9 |
| 文字の安全域 | 大事な文字は**中央の80%以内**。上下の端は3〜4%切られる |
| メインコピーの文字数 | **25文字以内**（バッジ・カードの短い語は別勘定） |
| 文字の占有 | タイトルで**画面の左55〜60%を上から下まで**使う。行間は狭く密着させる |
| 色数 | 3〜4色。`~/yuryo-kit-live/profile.md` の「7. 画像の好み」から引く |

> **`profile.md` の「入れたくないもの」が、この型の指定より優先。**
> ぶつかったら、型のほうを削る。たとえば「キラキラした装飾はNG」なら、**4方向のきらめき・月桂樹の輪・ハーフトーンの点々**を描かない。
> 「人物のイラストを入れない」なら、右側は物のイラストだけにする。**プロンプトの【禁止】に、その言葉をそのまま書く。**


### 全部の型に共通する骨格（これがいちばん効く）

1. **助詞（を・に・で・は・が）だけ一回り小さく描く。** これだけで日本語のサムネイルは締まる
2. **タイトルは3段。真ん中の段をアクセント色にして、一番大きくする**
3. **タイトルの下に必ず「帯」を1本置く**（サブタイトルの役割）
4. **右40%はイラスト。** ノートパソコンを描くときは、**画面の中にアプリの画面まで描き込む**（サイドバー・一覧・進捗バー・チェックリスト）。真っ白な画面にしない
5. **背景は白に近く**、淡いアクセント色の波形・ハーフトーンの点々・4方向のきらめきで軽く飾る

---

## 型A：完全ガイド型（迷ったらこれ）

いちばん使い回しが効く型。ノウハウ記事・手順記事・まとめ記事のほぼ全部に使える。

**背景**
- ほぼ白（極薄いクリーム）。**挿入図解より一段明るくする**（理由は `SKILL.md` の「色の決め方」）。右下と左下に淡いアクセント色の波形の曲線
- 左上と右上にアクセント色のハーフトーンの点々（小さな丸の格子）
- 4方向に伸びる菱形のきらめきを3個、淡いアクセント色で

**左上のバッジ**
- アクセント色塗りの**横長のカプセル形**。中に白いしおりのアイコンと白の太字（「保存版」「初心者OK」など）
- バッジの左上に**手書き風の短い集中線を3本**

**タイトル（左57%、3段）**
1. 黒の極太
2. **アクセント色の極太。ここが一番大きい**
3. 黒の極太

**タイトル下の帯**
- アクセント色塗りの、**左右の端がとがった矢羽根型**（横長の五角形）
- 中に白抜きの極太文字。帯の内側に細い白の枠線を一周させる
- ※白地＋アクセント色の太枠の角丸長方形に、アイコン＋2行の文字、という形でもよい

**右上の工程フロー**（要らなければ省く）
- 白い角丸カードを4枚、横一列。各カードに黒い線画アイコン＋小さなラベル
- カードの間はアクセント色の矢印。全体をアクセント色の点線でゆるく囲む

**右側のイラスト**
- ノートパソコンを斜め上から見た立体的な図。やわらかい影
- **画面の中にアプリのUIを描く**：左に細いサイドバー、中央に一覧、上に進捗バー、下にチェックマーク付きのリスト
- パソコンの奥から白い書類が数枚重なって飛び出す、成長の矢印と棒グラフ、など補助を1つ添える
- パソコンの代わりに**丸っこい笑顔のロボット**でもよい

**右下の丸バッジ**（要らなければ省く）
- 白い円を**月桂樹の輪**が囲み、上に星を3つ。中に黒の太字で2行

**下部の特徴リスト**
- 画面下端に白い角丸の横長の帯。中に4項目を等間隔、細い縦線で仕切る
- 各項目はアクセント色の線画アイコン＋黒の2行の短文

---

## 型B：ロードマップ型

「日数」「ステップ」で区切った記事に使う。型Aの下部を、工程カードの列に置き換えた形。

- 背景・バッジ・タイトルの作りは型Aと同じ
- タイトル下の矢羽根帯まで同じ
- **下部を大きく取り、白い角丸カードを5枚横並び**にする
  - 各カードの上辺にアクセント色のタグ（「Day1」「01」など）を乗せる
  - カードの中は黒い線画アイコン＋2行のラベル
  - カードの間はアクセント色の三角矢印
- 右のイラストは小さめにして、下部のカード列に場所を譲る
- 右上に**手書き風の吹き出し**（「AIで副業を加速!」など）を添えると軽くなる

**別配色にするとき**：濃紺 `#1B3B5A` ＋ティール `#2AA9A0` の組み合わせが合う。
その場合、主役の段だけ**極太の明朝体**にすると、落ち着いた「保存版」の空気が出る。

---

## 型C：特典・保存版型

特典つき・数字を推す記事に使う。**ここだけ質感を盛る。**

- 背景はクリーム `#FDF6EC`＋中央から放射状の淡い光。外周に細い金の角丸枠
- 左上に**深紅の帯**が斜め45度に横切る（両端に折り返しの影）
- タイトルは4段。3段目の主役は**画面の高さの3分の1**の巨大文字。アクセント色の塗り＋**太い白の縁取り**＋下方向の影
- 4段目はアクセント色の角丸バー。右端に**赤いリボンを結んだ金色のギフト箱**
- 右上に**金色の円形メダル**（月桂樹の輪＋王冠＋V字に垂れる赤リボン＋光沢）
- 右側は人物のイラスト（**クリーンなアニメ調**。髪に艶、服にしわ、頬に赤み）。まわりに白い吹き出しカードを3枚

**この型だけは「情報密度が高く、立体感のある装飾を使う。フラットにはしない」と書く。**
型A・型Bで同じことを書くと、うるさくなって失敗する。

---

## プロンプトのひな形

型を選んだら、上の説明を**要約せずそのまま書き写す**。
数値（左57%、4枚、3個、3本）まで含めて書くこと。省くと途端に貧弱になる。

```
/imagegen で画像を1枚だけ作って。サイズや品質の細かい確認は不要。生成できたら cp コマンドでコピーするだけにして（sips やリサイズは絶対に使わない）。

【モデル】Codex内蔵の image_gen（gpt-image-2 / Image 2.0）。CLIフォールバックは使わない
【用途】日本のnote記事の見出し画像。16:9。クリーンで整理された情報デザイン。3D的な立体文字や金色の装飾は使わない
【背景】（型の「背景」をそのまま書き写す）
【左上のバッジ】（型のとおり）
【タイトル】画面の左57%を使い、上から下まで詰めて配置する。極太ゴシック。行間は狭く密着させる。助詞（を・に・で）だけ一回り小さく描く
（1〜3段目を、色と大小の指定ごと書き写す）
【タイトル下の帯】（型のとおり）
【右上の工程フロー】（型のとおり）
【右側のイラスト】（型のとおり。画面の中のUIまで描写する）
【右下の丸バッジ】（型のとおり）
【下部の特徴リスト】（型のとおり）
【文字】日本語はすべて正確に、崩れずに描くこと。次の文言を一字一句そのまま描く：
（画像に出す文言を全部そのまま列挙する。要約させない）
【禁止】指定外の文字、英語の混入、ウォーターマーク、絵文字、金色の装飾、立体的な縁取り文字、写真
【保存】cp で <保存先の絶対パス> へコピーする
【報告】モデル名と保存先パスの1行だけ
```

> 型Cのときだけ、【用途】を「情報密度が高く、立体感のある装飾を使う。フラットでミニマルにはしない」に差し替え、
> 【禁止】から「金色の装飾」「立体的な縁取り文字」を外す。

> **サムネイルは記事フォルダの直下に `thumbnail.png` として置く。** `images/` の中ではない。
> あわせて `article.md` の先頭に `thumbnail: ./thumbnail.png` の1行を入れる。

## 部品が欠けたときの直し方

指定した部品が全部は描かれないことがある。**これは失敗ではなく、要素の詰め込みすぎが原因**なので、
同じプロンプトで粘らずに、次の順で手を打つ。

**予防（最初からこう書く）**

- **同じ種類の部品は2〜3個まで**。「カード3枚」より「カード2枚」のほうが確実に出る
- **絶対に入れたい要素から順に、番号を振って書く**。プロンプトの後半に書いた要素ほど落ちやすい
- **要素は7つまで**。型ごとの目安は下の表

| 型 | 要素数 | 欠けやすさ |
|---|---|---|
| 型A：完全ガイド | 7 | 出やすい |
| 型B：ロードマップ | 6 | 出やすい |
| 型C：特典 | 8 | **欠けやすい。浮遊カードは2枚にとどめる** |

**欠けたとき**

1. 落ちた要素を指摘して作り直すのではなく、**別の要素を1つ減らして**作り直す
2. 作り直しは**2回まで**。3回目は要素を減らした構成にするか、型を変える
3. 保存先の名前は毎回変える（同じ名前だと上書き確認で止まる）

**そもそも欠けても困らない要素**（削る候補、この順に削る）

工程フロー → 丸バッジ → きらめき → 浮遊カード → 下部の特徴リスト

タイトル・帯・イラストは削らない。この3つが欠けたら作り直す。

## 確認のポイント

サムネイルは記事の顔なので、図解より厳しく見る。**1つでも欠けたら作り直す。**

- [ ] 日本語が崩れていないか（1文字でも崩れたら作り直す）
- [ ] **助詞が小さくなっているか**（同じ大きさだと素人っぽく見える）
- [ ] **タイトルの下に帯があるか**
- [ ] **ノートパソコンの画面が真っ白になっていないか**（UIが描かれているか）
- [ ] かぎかっこ・記号が省略されていないか（「」『』＋ は落ちることがある）
- [ ] 指定していない文字・英語が勝手に入っていないか
- [ ] 左側に間の抜けた余白ができていないか
- [ ] **指定した部品が全部入っているか**（カードが4枚指定で3枚になる、など欠けやすい）
- [ ] 人物やロボットの手・顔が崩れていないか
- [ ] 大事な文字が端で切れていないか
- [ ] スマホの一覧で親指サイズになっても、主役の文字が読めるか
