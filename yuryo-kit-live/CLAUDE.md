## あなたの振る舞い

- 常に日本語で話す

### 0. 動作環境の確認

- OSを確認する。MacとWindowsに対応（Windowsはベータ。最初に「Windows対応はベータ版です。困ったら遠慮なく相談してください」と一言伝える）
- **Windowsでは、以下のコマンドをすべてPowerShell向けに読み替えて実行する**（読み替え例は `Windows導入ガイド.md` にある。パスは `~/yuryo-kit-live` → `$HOME\yuryo-kit-live`）
- `node -v` でNode.jsを確認する。無ければ [nodejs.org](https://nodejs.org/ja) からの導入を案内し、入ってから再開する

### 1. フォルダを正しい場所に置く

このキットは `~/yuryo-kit-live`（ユーザーフォルダ直下。Windowsなら `C:\Users\名前\yuryo-kit-live`）にないと動かない。

- **最初に二重フォルダを確認する**：zipの解凍のしかたによって `yuryo-kit-live/yuryo-kit-live` と入れ子になっていることがある。`CLAUDE.md` と `note-draft` が直下に見えるほう（内側）が本体
- 今の場所が `~/yuryo-kit-live` ならそのまま次へ
- 違う場所にあるなら、`~/yuryo-kit-live` へ**コピー**する（元は消さない）
- `~/yuryo-kit-live` に別の中身が既にあるときは、上書きせず相手にどうするか確認する
- **以後の作業はすべて `~/yuryo-kit-live` 側で行う**
- コピーした場合は、**相手にもそのことを必ず伝える**。相手はいま元のフォルダ（デスクトップ等）をClaude Codeで開いているので、そのままだと設定ファイルを直すときに空のほうを編集してしまう
  > 正式な置き場所は `~/yuryo-kit-live` になりました。元のフォルダはもう使いません。設定を直すときは `~/yuryo-kit-live/profile.md` を開いてください。

### 2. スキル（AIの作業手順書）を読み込ませる

**先に、同じ名前のスキルが既に無いか確かめる。**

```bash
ls ~/.claude/skills 2>/dev/null
```

`yuryo-live-note` `yuryo-live-image` `yuryo-live-toukou` のどれかが既にあったら（前にこのキットを入れたことがある場合）、**上書きせずに退避してから**進める。退避することを一言伝えてから実行する。

```bash
mkdir -p ~/.claude/skills-backup && cp -RL ~/.claude/skills/yuryo-live-note ~/.claude/skills/yuryo-live-image ~/.claude/skills/yuryo-live-toukou ~/.claude/skills-backup/ 2>/dev/null; echo done
```

**`-RL` の `L` を落とさないこと。** `~/.claude/skills` がショートカットになっている環境だと、`L` なしでは中身が退避されずに空のまま進んでしまう。

> 無料の「note記事づくりキット」（`note-image` など）や「有料note作成キット」（`yuryo-note` など）の手順書が入っていても、**名前が違うので上書きしない。そのまま残してよい。**

そのうえでコピーする。

```bash
mkdir -p ~/.claude/skills && cp -r ~/yuryo-kit-live/skills/* ~/.claude/skills/
```

### 4. 画像づくりの道具を選んでもらう

まず、すでに入っているか確認する。

```bash
codex --version
```

**番号が出たら**「画像づくりの道具はすでに入っています」と伝えて次へ進む。

**「command not found」と出たら**、相手に選んでもらう。どちらを選んでも、あとから変えられることを添える。

> 画像づくりには2つの選び方があります。
> **A：Codex（コーデックス）を入れる**（おすすめ）
> ChatGPTの有料プラン（月20ドル〜）をお持ちなら、追加料金なしで**サムネイル（見出し画像）とイラストまで**作れます。導入は1コマンド、数分です。
> **B：入れずに進む**
> 記事の中に差し込む図解だけを作ります。追加料金は一切かかりません。見出し画像はご自身で用意していただく形になります。

Aを選ばれたら、次を案内する。

```bash
npm install -g @openai/codex
```

入れ終わったら、初回だけ `codex` と打ってChatGPTアカウントでログインしてもらう。

> **`codex` はあなた（AI）が実行してはいけない。** 対話式なので、あなたが実行すると応答待ちのまま止まる。
> 相手のターミナルで打ってもらい、「ログインできましたか」と確認して次へ進む。
> **ログイン情報を聞いたり、代わりに入力したりしてもいけない。**

Bを選ばれたら何もせず次へ進む。あとから気が変わったときは、上のコマンドを実行すれば同じことができると伝えておく。

**結果を `~/yuryo-kit-live/profile.md` の「7. 画像の好み」の「Codexを入れたか」に書き込む**（入っていた・Aで入れた →「入れた」／B →「入れていない」）。画像づくりのたびに聞き直さないため。

**1つずつ聞く。** まとめて並べると答えるのが負担になる。

## 記事づくり（8問・必須）

**質問1：誰に向けて、何について発信していますか？**

読者像・その人の悩み・あなたのテーマや仕事。
「2. 誰に向けて書くか」の4つの欄（年代・性別／どんな状況の人か／抱えている悩み／読んだあとどうなってほしいか）が**全部埋まるように**聞く。決めていない欄は「特に決めていない」と書く。
→ `profile.md` の「1. あなたのこと」「2. 誰に向けて書くか」へ

**質問2：過去に書いた文章を200字ほど貼ってください**

記事の「あなたらしさ」を一番左右する。SNSの投稿でも、メールでもよい。空だとその人の文章にならないので、ここは特に粘る。
→ 「3. 文章のトーン」の「文章のサンプル」欄へ

貼ってもらったら、**一人称・よく使う語尾・敬語のレベル・避けたい言い回し**を読み取って「3. 文章のトーン」の表に書き込み、「こう読み取りました。合っていますか」と確かめる。避けたい言い回しが見当たらなければ「特になし」と書く。

**質問3：何を教える有料noteを作りたいですか？ 読んだ人は何ができるようになりますか？**

有料noteの中身そのもの。「できるようになること」は**行動が変わる形**で聞く（「◯◯がわかる」ではなく「◯◯ができる」）。
→ 「6. 売る記事のこと」へ

**質問4：いくらくらいで売りたいですか？**

決まっていなければ「1,000〜3,000円くらい」でよい。**最終的な値段は、記事ができてから本人が決める。**
→ 「6. 売る記事のこと」の価格帯へ

**質問5：買った人からの返金申請を受け付けますか？**

noteは**何も設定しないと「受け付ける」状態**で公開される。知らないまま出さないために必ず聞く。
→ 「6-3. 返金について」へ

**質問6：この記事で、無料で見せてよいところと、有料にしたいところはありますか？**

決まっていなければ「おまかせ」でよい（その場合は記事ができてからAIが提案する）。「おまかせ」なら、2つの欄の両方に「おまかせ」と書く。
**答えは無料で見せて、手順を有料にする**のが基本だと一言添える。
→ 「6. 売る記事のこと」の「無料で見せる範囲」へ

**質問7：うまくいかなかった経験を、1つ教えてください**

読者が信用するのは成功談ではなく失敗談。カッコ悪い話ほど効く。一言で十分だと伝える。
→ 「4. 自己開示に使えるエピソード」へ

**質問8：記事の最後で何をすすめたいですか？**

公式LINE・セミナー・別の商品など。無ければ「なし」でよい（「いちばんすすめたいもの」に「なし」と書く）。
→ 「5. 記事の最後に何をすすめるか」へ

## 文章と画像の好み（6問・任意）

ここからは空欄でも動く。**答えるほど記事が自分に近づく**と伝えてから始める。

**質問9：読者にどう呼びかけますか？**（あなた／みなさん／名前を呼ぶ／呼びかけない）
→ 「3-2. 文章の好み」へ

**質問10：絵文字は使いますか？　太字は多めと少なめ、どちらが好みですか？**
→ 「3-2. 文章の好み」へ

**質問11：文章の雰囲気を寄せたい書き手はいますか？**（名前かURLで1〜3人。無ければ「なし」）
→ 「3-2. 文章の好み」へ

**質問12：書きたくない話題や、触れられたくないことはありますか？**（無ければ「なし」）
→ 「6-4. 使ってはいけない表現」へ。**画像にも出さない**

**質問13：見出し画像（サムネイル）の型と色を教えてください**

**先に「画像の見本」フォルダを開いてもらう。** 実物を見ると決めやすい。
型はA・B・Cの3つ（見本のサムネイル6枚）。色は「メインの色」を1つ決めるだけでよい。分からなければ空欄で、初期設定のオレンジになる。
→ 「7. 画像の好み」の「サムネイルの型」「色」へ

> Codexが入っていない場合は、型は聞かずに色だけ聞き、「見出し画像はご自身で用意していただく形になります」と一言添える。

**質問14：記事に入れる画像の好みを教えてください**（人物のイラストを入れるか／操作画面のスクリーンショットを使うか／入れたくないもの）
→ 「7. 画像の好み」の「記事に差し込む画像」へ

> Codexが入っていない場合、人物のイラストは作れない。「入れない」と書いてから、操作画面と入れたくないものだけ聞く。

## あなたらしさ（6問・後からでもいい）

**文章と画像の好みの6問が終わったところで、もう一度区切る。**

> ここまでで十分です。
> このあと6問ありますが、これは「AIっぽさを消す」ための質問です。答えると文章の顔が変わります。
> 今でも、あとから思い出したときでも構いません。どうしますか。

答えは `profile.md` の「9. あなたらしさを深める」へ書き込む。

**質問15：口ぐせや、よく使う言い回しはありますか？**（2〜3個）

**ここが一番効く。** 語尾をそろえてもAI感は消えないが、実際に口に出す言い回しが入ると文章の顔が変わる。
「思いつかない」と言われたら、**過去の投稿を一緒に見て、繰り返し出てくる言葉を拾ってあげる**。

**質問16：説明するとき、よく使うたとえはありますか？**

例：料理にたとえる、部活にたとえる、引っ越しにたとえる。
その人の説明のクセなので、記事全体で同じたとえを使うと一貫します。

**質問17：この分野に入ったきっかけは何でしたか？**（いつ・何があって）

無料パートの自己開示の起点になる。**「いつ」を必ず聞く**（時期が入ると急に本当の話になる）。

**質問18：今でも苦手なこと・できないことはありますか？**

**できないことを書くほど、読者は安心する。** 完璧な人の話は自分ごとにならない。
言いにくそうなら「僕もこれは今でもダメで」と一例を出して促す。

**質問19：読者からよく聞かれる質問は何ですか？**（3つまで）

**そのまま章の見出しになる。** 発信をしていない人には「友人や同僚から聞かれること」で聞く。

**質問20：自分の写真を記事に使いますか？**（使う／使わない）

「使わない」なら、人物イラストか図解だけで作る。
→ 「9. あなたらしさを深める」の顔出しの欄へ

## 「入稿して」と言われたら

記事ができたあと、noteの下書きに入れる工程。**あなた（AI）が実行する。相手にターミナルを開かせない。**

```bash
cd ~/yuryo-kit-live/note-draft && npm run draft -- articles/<記事名> --headed
```

- 下書きを作るだけで、**公開はしない**。ここは絶対に自動化しない
- ブラウザが開いて1分半ほどかかる。途中で止めない
- 終わったら下書きURLをそのまま伝え、タグは手で貼ってもらうよう案内する
- 「ログインしてください」と出たら `npm run login` を実行し、**相手自身に**ログインしてもらう

### 入稿が終わったら、必ずこの4つを伝える

有料noteは、入稿だけでは売れる状態にならない。

**道具が入稿の最後に「ここから先は、あなたの手で設定してください」と4行出す。** 記事フォルダと `profile.md` から読んだ実際の値が入っている。**その内容をそのまま相手に伝える。暗記して言い直さない。**

1. **有料ラインの位置**（どの見出しの直前か）
2. **販売価格**
3. **返金申請の設定**（何もしないと「受け付ける」状態）
4. **タグ**（下書き画面で貼ってもらう）

「空欄です」と出た項目は、`profile.md` のどこを埋めればよいかも一緒に伝える。

そのうえで、こう伝える。

> 有料設定・価格の入力・有料ラインの設定・公開は、noteの編集画面でご自身の手で行ってください。ここは自動化していません。

## 困りごとの対応

- 手動でやりたい・詳しく知りたい → `はじめにお読みください.md` を案内する
- 入稿が失敗する → `note-draft/README.md` の復旧手順（selectors.ts）を見る
- ログインが切れた → `npm run login` をもう一度
- 採点・リライト・目次の自動挿入・売れないときの診断・Notionへの保存を頼まれた → **このキット（ライブ版）には入っていない**と正直に伝える
- 「yuryo-kit-liveをやめたい」と言われた → `00_はじめに読む注意書き.md` の「5. やめたくなったら」に従う。**何をゴミ箱へ移すかを先に見せて、確認を取ってから**実行する。完全には消さない
