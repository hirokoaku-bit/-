## 2. いちばん簡単な導入（おすすめ）

ターミナルを触らずに、AIにセットアップを任せる方法です。

1. Claudeアプリを開いてログインする
2. 上の「**Code**」タブを選ぶ
3. 「フォルダを選択」で、この `yuryo-kit-live` フォルダを選ぶ
4. 入力欄に「**セットアップして**」と打ってEnter

あとはAIが案内してくれます。全体で5〜10分ほどです。途中であなたがやることは3つだけ：

- **画像づくりの道具を選ぶ**（ChatGPTの有料プランがあるなら「入れる」がおすすめ。無ければ「入れずに進む」でOK）
- 開いたブラウザで**noteにログインする**（パスワードは保存されません）
- **質問に答える**（必須8問。誰に向けて書くか／文章サンプル200字／何を教える記事か／いくらで売るか／返金を受け付けるか／無料と有料の切り分け／うまくいかなかった経験／記事の最後にすすめるもの）
  - **必須8問が終わったところで一度区切れます。** そのあとに文章と画像の好み6問、さらに「あなたらしさ」6問（合計20問）があり、答えるほど記事が自分の文章に近づきます
  - **最後の6問は、あとから思い出したときに書き足しても構いません**（口ぐせ・この分野に入ったきっかけ・今でも苦手なこと・読者からよく聞かれる質問など）

終わったら、**Claudeを一度閉じて開き直してください。** これで準備完了です。

> 手動でやりたい方、途中でうまくいかなかった方は、次の「手動で導入する場合」へ。

## 3. 手動で導入する場合

> ここから下のコマンドはMac用です。**Windowsの方は `Windows導入ガイド.md` を見てください。**

### Step 1. フォルダを置く

このキットのフォルダ（`yuryo-kit-live`）を、**ユーザーフォルダの直下**に置いてください。

- `書類` や `デスクトップ` ではなく、その1つ上（自分の名前のフォルダ）です
- 置いたあとの場所が `~/yuryo-kit-live` になっていればOKです
- フォルダ名が `yuryo-kit-live 2` のように変わっていたら、`yuryo-kit-live` に直してください

> **なぜ場所が決まっているの？**
> AIが設定ファイルを探しに行く場所を、あらかじめ決めてあるためです。別の場所に置くと見つけられません。

### Step 2. スキルをClaude Codeに読み込ませる

ターミナル（`アプリケーション` → `ユーティリティ` の中にあります）を開いて使います。

> **前にこのキットを入れたことがある方へ。**
> このキットは `yuryo-live-note` `yuryo-live-image` `yuryo-live-toukou` という名前の手順書を入れます。
> **同じ名前のものがあると、上書きされます。** 先に次の1行を実行して、控えを取ってください。
> 心当たりがない方も、実行して損はありません（該当が無ければ何も起きません）。
>
> ```bash
> mkdir -p ~/.claude/skills-backup && cp -RL ~/.claude/skills/yuryo-live-note ~/.claude/skills/yuryo-live-image ~/.claude/skills/yuryo-live-toukou ~/.claude/skills-backup/ 2>/dev/null; echo 控えを取りました
> ```
>
> 控えは `~/.claude/skills-backup` に入ります。元に戻したくなったら、この中から戻せます。
>
> 無料の「note記事づくりキット」や「有料note作成キット」をお使いの方も、**手順書の名前が違うので上書きされません。**

そのうえで、次の1行をコピーして貼り付け、Enterを押します。

```bash
mkdir -p ~/.claude/skills && cp -r ~/yuryo-kit-live/skills/* ~/.claude/skills/
```

**そのあとClaude Codeを一度閉じて、開き直してください。** 起動しなおさないと、新しいスキルが認識されません。

### Step 3. 設定ファイルを埋める

`yuryo-kit-live` フォルダの中にある **`profile.md`** を開いて、あなたの情報を書いてください。

ここが記事の質をいちばん左右します。**有料noteでは、特に次の5つが重要です。**

1. **文章のトーン**（一人称・語尾）… **必須**。空だと、あなたの文章になりません
2. **あなたが書いた文章のサンプル**（200字ほど貼るだけ。ここが「あなたらしさ」を一番決めます）
3. **6. 売る記事のこと**（何を教えるか・読んだ人ができるようになること・価格帯）… **必須**
4. **6-3. 返金について**（受け付けるかどうか）… **必須**。何もしないと「受け付ける」状態で公開されます
5. **うまくいかなかった経験**（読者が信用するのは成功談より失敗談です）

次は空でも進みます。空ならAIが記事の内容から判断して提案します。

- 無料で見せる範囲／有料にしたいところ
- ジャンル特有の注意（薬機法など）
- 画像の好み

あとから何度でも直せます。

### Step 4. note入稿ツールの準備

ターミナルで、次を**上から順に1行ずつ**実行します。

```bash
cd ~/yuryo-kit-live/note-draft
```

```bash
npm install
```

> 部品をダウンロードします。1〜3分ほどかかります。文字がたくさん流れますが、正常です。
>
> 最後に英語で「vulnerabilities（注意が必要な部品）」と出ることがあります。2026年9月14日の時点で出ているのは、**動作確認のテストだけに使う部品（vitest）の注意2件**で、記事づくりとnoteへの入稿には使っていません。そのまま進めて大丈夫です。表示に出てくる `npm audit fix` も、実行しなくて大丈夫です。

```bash
npx playwright install chromium
```

> ブラウザを自動で動かすための部品を入れます。**150MBほどのダウンロードが走るので、数分かかることがあります。**

```bash
npm run login
```

> ブラウザが開きます。**あなたが手でnoteにログイン**してください。ログインを検知すると自動で閉じます。
> パスワードは保存されません。「ログイン済みの状態」だけがパソコンの中に保存されます。
> なお、ログインの確認のために編集画面を一度開くので、**noteに空の下書きが1件できます。** 中身は空なので、下書き一覧から消してしまって大丈夫です。

### Step 5. 画像づくりの道具（任意・飛ばしてもOK）

ChatGPTの有料プラン（月20ドル〜）をお持ちの方だけ、こちらもどうぞ。
入れると、**記事の顔になる見出し画像と人物イラスト**まで、追加料金なしで作れるようになります。

```bash
npm install -g @openai/codex
```

入れ終わったら、次を打ってEnter。ChatGPTアカウントでのログインを1回だけ求められます。

```bash
codex
```

> **入れなくても大丈夫です。** その場合は、記事に差し込む図解だけを作ります。あとから足すこともできます。

これで準備完了です。

## 4. 1本書いてみる

Claude Codeを開いて、こう伝えるだけです。

```
有料noteを1本作って
```

テーマが決まっているなら、こう言ってください。

```
「AIで議事録を10分で作る手順」で有料noteを作って
```

### そのあとの流れ

無料の記事と違い、**9つの工程を順番に通ります**。途中で**4回止まって**、あなたに聞きます。

1. **企画**：誰に・何を・どこから有料にするかを決めます
2. **構成**：無料パートと有料パートを設計します
3. **確認①**「この構成で本文を書いていいですか？」← **ここで止まります**
4. **材料集め**：あなたにしか書けない話を聞きます ← **ここで止まります**
5. **有料パートを書く**（無料パートより先に書きます）
6. **確認②**「価格は◯◯円でよいですか？」← **ここで止まります**
7. **無料パートを書く**
8. **画像**：1枚ずつ作って、できるたびにお知らせします → 記事フォルダに書き出し
9. **確認③**「noteに下書きを入れますか？」← **ここで止まります**

### 材料集めについて（ここがいちばん大事）

このキットは、**白紙からAIに書かせません。**

本文を書く前に、章ごとの材料を聞かれます。

- 詰まった場所と、その直し方
- なぜその方法を選んだのか
- やってみて分かった注意点
- 読む人への呼びかけ

雑な箇条書きで大丈夫です。ここが空のまま進めると、「大切なのは継続することです」のような、誰が書いても同じ文章になります。

**面倒に見えますが、ここを飛ばすと出てくるものが変わります。**

### noteに下書きを入れる

そのまま、こう伝えるだけです。

```
入稿して
```

ブラウザが自動で開き、タイトル・本文・画像が入力され、下書きが保存されます。**1分半ほどかかります。触らずに待ってください。**

### 入稿したあと、あなたの手でやること

**ここは自動化していません。** noteの編集画面で、次を行ってください。

1. 記事の種類を「有料」にする
2. 販売価格を入力する
3. **有料ラインを、指定された見出しの直前に置く**
4. 見出し画像を確認する
5. 無料部分をスマホ表示でプレビューする
6. **返金申請の設定を確認する**（何もしないと「受け付ける」状態です）
7. 公開する

入稿が終わると、有料ラインの位置・価格・返金設定・タグを画面に表示します。そのとおりに設定してください。

> 自分でコマンドを打ちたい方は、こちらでも同じことができます。
>
> ```bash
> cd ~/yuryo-kit-live/note-draft && npm run draft -- articles/記事の名前 --headed
> ```

## 5. できること・できないこと

### できること

- 企画づくり（誰に・何を・いくらで売るか）
- **無料パートと有料パートの設計**（どこで切るかの判断も含みます）
- 本文執筆（あなたの材料をもとに書きます）
- **価格の提案**（手数料を引いた手取りの目安も出します）
- 景表法・特商法まわりの整理（価格を決める工程で、書いてはいけない表現と但し書きを確認します）
- 事実確認（ツールの機能や料金などをネットで調べて裏を取ります）
- **見出し画像（サムネイル）の作成**（Codexを入れた方だけ）
- 記事に差し込む図解の作成
- 人物イラストの作成（Codexを入れた方だけ）
- 操作画面のスクリーンショット（赤枠・矢印・注釈を入れられます）
- noteの下書きに入れるところまで（見出し・太字・箇条書きも付いた状態で入ります）
- **出す前の検査**（図の印の消し忘れ・書きかけの文字・メールアドレスなどを、入稿の前に知らせます）
- **入稿後に、手で設定する4つを画面に出す**（有料ラインの位置・価格・返金設定・タグ）

### このキット（ライブ版）に入っていないもの

- 構成と本文の点数づけ（点数に届くまで自動で直す仕組み）
- 目次の自動挿入
- 図をまとめて作る機能
- 表の画像・Before/After・ワークシート・手順の連結図・カード型の図・実績の画面・毎回入れるバナー
- 売れないときの診断
- Notionへの保存

### できないこと

**お金にかかわる操作は、すべてあなたの手で行います。**

- **有料設定・価格の入力・有料ラインの設定はしません**
- **公開ボタンは押しません**
- 返金設定の変更もしません（確認をうながすだけです）

あえてそうしています。自分が読んでいない文章が、自分の名前で、値段つきで世に出る。これがいちばん怖いからです。

### 画像は何で作られるのか

| あなたの環境 | 作れるもの | かかる料金 |
|---|---|---|
| Codexを入れた（ChatGPT有料プラン） | 見出し画像・図解・人物イラスト | **追加料金なし** |
| 入れていない | 図解のみ | **追加料金なし** |

操作画面のスクリーンショットは、どちらでも作れます。

**1枚あたり2〜3分かかります。** 有料noteは長いので、枚数もそれなりになります。

| 記事の長さ | 画像の枚数の目安 | 画像にかかる時間 |
|---|---|---|
| 3,000字前後 | 5〜6枚 | 15〜20分 |
| 10,000字前後 | 15〜25枚 | 40分〜1時間 |
| 30,000字以上 | 50枚以上 | **2〜4時間** |

**ここは正直にお伝えします。長い記事だと、画像だけで数時間かかります。**

画像は**1枚できるたびにお知らせします**。時間がかかりすぎるときは、「画像は◯枚までにして」と伝えてください。

見出し画像は、**下書きを作るときに自動で設定されます**。noteの画面デザインの変化などで入らなかったときは、
記事フォルダの `thumbnail.png` を、noteの画面で自分で選んでください（本文と挿入画像はそのまま入ります）。

### できないこと・割り切っていること

- **自動で公開はしません**（誤公開を防ぐためです）
- **Codexを入れていない場合、見出し画像は作れません**。ご自身で用意していただく形になります
- **見出し・太字・箇条書き・番号リストは、そのまま下書きに入ります**。noteの画面で付け直す必要はありません
- **表は箇条書きに変わります**。note側に表を作る機能がないためです。「項目：説明」の形で並びます。表の見た目のまま載せたいときは、ご自身で画像にして貼ってください
- **タグ（ハッシュタグ）は自動では入りません**。記事に付けるタグは入稿の最後に画面に出すので、noteの下書き画面で貼ってください
- **実行するたびに新しい下書きが1件増えます**。同じ記事で2回試すと2件できます。要らないものはnoteの下書き一覧から手で消してください
- **予約投稿・既存記事の編集・削除はしません**

## 6. 困ったときは

| こうなったら | こうしてください |
|---|---|
| Claudeが「有料noteを1本作って」に反応しない | Claudeを閉じて開き直す（セットアップのあとは再起動が必要です） |
| 「セットアップして」と打っても案内が始まらない | 「Code」タブで `yuryo-kit-live` フォルダを選べているか確認する |
| 「設定ファイルが見つかりません」と言われる | `yuryo-kit-live` フォルダの置き場所を確認する（`~/yuryo-kit-live` になっているか） |
| ログインしてくださいと出る | Claudeに「noteにログインし直したい」と伝える（ブラウザが開くので、あなたがログインします） |
| 途中で止まった・エラーが出た | 同じコマンドを繰り返さず、画面に出ている文章をそのままClaude Codeに貼って相談する |
| 部品のダウンロードの最後に、英語で「vulnerabilities」と出た | 2026年9月14日時点では、動作確認のテストだけに使う部品の注意です。記事づくりと入稿には使っていないので、そのまま進めて大丈夫です。数や中身が違うときは、Claudeに「この注意は何？」と聞いてください |
| タイトル欄が見つからない、と出る | noteの画面デザインが変わった可能性があります。Claude Codeに「note-draftのselectors.tsを直して」と伝えてください |
| **「差し込み待ちの印が残っています」と出て、入稿できない** | 図を入れる場所の印（`［図：〜］`）が本文に残っています。**そのまま入稿すると、この文字が記事に出ます。** Claudeに「図を作って差し込んで」と伝えるか、その図を使わないなら本文から消してください |
| **「リスト行に全角スペースがあります」と出て、入稿できない** | 箇条書きの行に全角の空白が入っています。**これがあるとnoteのリストが壊れて、以降が全部箇条書きに巻き込まれます。** Claudeに「全角スペースを直して」と伝えてください |
| 「書きかけらしき文字があります」と出る | 「（ここに〜）」のような書きかけが残っています。**入稿は止まりません**が、直してから出すことをおすすめします |
| 記事の内容が自分らしくない | `profile.md` の「文章のサンプル」を長めに貼り直すと、ぐっと近づきます |
| 見出し画像が作られない | 画像づくりの道具が入っていない可能性があります。`codex --version` を実行して、番号が出るか確認してください |
| 画像づくりが途中で止まったように見える | 1枚あたり2〜3分かかります。文字が流れているうちは動いています。5分以上変化がなければClaude Codeに相談してください |
| 画像の文字が崩れている・違う文字が入る | Claude Codeに「この画像を作り直して」と伝えてください。作り直しに追加料金はかかりません |
| 画像の色や雰囲気が自分と違う | `profile.md` の「7. 画像の好み」で、サムネイルの型・色・人物イラストの有無を変えられます |

### 環境を点検する

うまく動かないときは、Claudeに「**環境を点検して**」と伝えてください。足りないものがあれば教えてくれます。

自分で確認したい方は、こちらでも同じことができます。

```bash
cd ~/yuryo-kit-live/note-draft && npm run doctor
```

## 安全のために

- このキットには、**あなた以外のログイン情報やAPIキーは入っていません**
- `npm run login` で保存されるログイン状態は、あなたのパソコンの中だけに残ります
- **このフォルダを誰かに渡すときは、`note-draft/storage/` の中身と `.env` を必ず消してください**。あなたのnoteを操作できてしまいます
- 記事の本文や画面のスクリーンショットは `logs/` `screenshots/` に残ります。共有する前に中身を確認してください
