# yuryo-live-note — 販売用の有料noteを1本作る

商品企画 → 構成 → 材料集め → 有料パート → 価格 → 無料パート → 画像 → 書き出し → 下書き投入 を順につないで、**売れる状態の有料noteを1本仕上げる**司令塔。

## 型の正

**`references/honnin-kata.md` が型の正。** 有料noteを実際に売っている書き手（きっしー）が、書き方を7工程で言語化したもの。

**一般的なライティング論で上書きしない。** 他の references と食い違ったら honnin-kata を優先する。

## 無料noteと違う3点

- **記事が2つに割れている**。買う前に読める無料パートと、買った人だけが読む有料パート
- **お金を受け取る**。誇大表現・再現性の断定・返金トラブルが実害になる
- **満足度が次の商品に直結する**。買って損したと思われたら、次の商品も発信も信用されなくなる

## 走らせ方

- **止まるのは4か所**：構成の承認／材料集め／価格の確定／note入稿
- **販売設定はしない**：note側の有料設定・価格入力・公開ボタンは**必ず人が手で行う**

> 各工程のルール本体は references にある。SKILL.md に写さず、都度読んで従うこと（二重管理しない）。

## 手順

### 0. profile.md を読む（最初にやる）

`~/yuryo-kit-live/profile.md` を最後まで読む。ここに読者・文体・価格帯・約束・誘導先が書いてある。

**次の欄が空なら、そこで止めて埋めてもらう。**

- 3. 文章のトーン（一人称・語尾）… 空だと、その人の文章にならない
- 6. 売る記事のこと（何を教えるか・できるようになること・価格帯）
- 6-3. 返金について

次の欄は空でも進める。空なら記事の内容から判断して提案する。

- 6. 無料で見せる範囲／有料にしたいところ
- 6-4. ジャンル特有の注意
- 7. 画像の好み

**続けて `references/honnin-kata.md` を最後まで読む。** 型はここが正。

### 0-2. どの工程から入るかを見る

ユーザーが工程を1つだけ頼んできたら、そこから入る。通しで頼まれたら1から順に走る。

| 頼まれ方 | 入る工程 |
|---|---|
| 「有料note作って」「有料noteを1本」 | 1から通しで |
| 「何を売るか決めたい」「企画を考えて」 | 1だけ |
| 「構成を作って」「見出しを考えて」 | 2 → 3（承認）で止める |
| 「この構成で本文書いて」（構成を貼ってきた） | 4から |
| 「無料パートだけ書いて」「冒頭を書いて」 | 7だけ（有料パートが無いときは先にそちらを促す） |
| 「価格を決めたい」「いくらで売る？」 | 6だけ |
| 「画像を作って」 | 8だけ |
| 「フォルダに書き出して」「noteに入れて」 | 9以降 |
| 「採点して」「リライトして」「目次を入れて」「売れない」「Notionに保存して」 | このキットには入っていない機能だと伝える |

### 1. 商品企画を固める

**ネタ候補を出す前に、既存記事との被りを確認する。** ここを飛ばすと、価格まで決めたあとにやり直しになる。

1. `~/yuryo-kit-live/note-draft/articles/` の中を見て、これまで書いた記事を把握する
2. 記事フォルダ（`<作業ディレクトリ>/articles/`）の見出しを見て、**何がどこまで書かれているか**を把握する
3. そのうえでネタ候補を出す

`references/kikaku.md` と honnin-kata の工程1に従って、**3つ**を決める。

- 読む人（1人に絞る）
- 読み終わった人ができるようになること
- **どこまで無料で、どこから有料にするか**

あわせて**完成の定義**を決める。数字は `profile.md` の「6-2. 記事の長さ」から引く。

- 無料パート・有料パートの文字数
- 章の数（決めたら増やさない）
- 1章あたりの文字数の**上限**（下限にしない）

不足している情報があれば聞く。**最大3問**。固まったら画面に出し、承認は求めず次へ進む。

### 2. 構成を作る

`references/kosei.md` と `profile.md` に従って構成を組む。

- **無料パートは4つだけ**（悩みの言語化／全体像／結論／予告）。盛らない
- **有料ラインは「分かった」の直後、「やってみよう」の直前**
- 有料パートの章は**読む人の作業順**に並べる
- 各章は5ブロック（なぜ／手順／具体例／つまずく場所／ゴール）で設計する
- H3は疑問形を主体にする
- 各章に型ラベル（【無料パート】【有料パート】）を付ける

### 3. 構成を見せて承認をもらう（**ここで止まる**）

構成を画面に出し、次を添える。

- この有料noteの狙い（3行）
- 買う理由（読者がお金を払う決め手）
- **有料ラインの位置と、そこで切る理由**
- 完成の定義（章数・1章の上限文字数）

そのうえで聞く。

> この構成で本文を書いていいですか？

OKが出るまで先に進まない。直しの指示が出たら直して、もう一度見せる。

### 4. 材料を集める（**ここで止まる**）

**白紙からAIに書かせない。** honnin-kata の工程5が根拠。ここを飛ばすと中身が薄くなる。

章ごとに、本人にしか書けない4つを聞く。

- 詰まった場所と、その直し方
- なぜその方法を選んだのかの理由
- やってみて分かった、注意しておくこと
- 読む人への呼びかけ、率直な感想

**順番を守る。いきなり聞かない。**

1. **先に既存資産から拾う**（過去のnote記事・SNSの投稿・セミナー資料・過去の下書き）。失敗談・数字・判断基準を横断で集める
2. 拾えたものを**画面に出して見せる**（「これで合っていますか」）
3. **足りない分だけ**聞く

いきなり聞くと、ユーザーから「過去のnoteを見て」と返ってきて1往復むだになる。

聞くときは**まとめて1回**。章ごとに何度も聞かない。

> 各章について、次を箇条書きで出してください（雑な日本語で大丈夫です）。
> 手順／つまずいた場所／具体的な数字／実際にあった失敗

材料が出そろわない章があれば、その章だけ**空のまま止めて報告する**。憶測や一般論で埋めない。

### 5. 有料パート本文を書く

`references/honbun.md` と `profile.md` に従って書く。**無料パートより先に書く。**

- 集めた材料をもとに書く。AIがやるのは並べ替え・言い回しの統一・見出し案・誤字チェック・長い文を割ること
- 各章は5ブロック。**手順が章の半分くらいの厚み**
- **画面に出ている言葉をそのまま使う。言い換えない**
- 買った直後の1画面は、お礼1行 → 前置きなしで現物
- プロンプト・テンプレは全文書き出す
- 各章末に「今日のゴール：〜」を置く
- 締めは**「今日やること」1つ**。長いまとめは書かない
- 書き終えたら想定質問を5つ出し、答えていないものを該当章に1〜2行足す
- 文字数は**上限**で管理する。超えたら削る。足りない章は水増ししない
- 文字数は Python で空白を除いて数える（`wc -m` は使わない）
- 図を入れたい場所には `［図：説明］` と1行書いておく（工程8で画像に差し替える）

### 6. 価格を決める（**ここで止まる**）

`references/hanbai.md` に従って、価格・返金方針・購入者特典・法律まわりの但し書きを固める。

**無料パートを書く前に決める。** 無料パートで価格に触れるため。

- `profile.md` の価格帯をもとに**推奨価格を1つ出す**。理由を3行で添える
- noteの販売価格の下限・上限と手数料は変わる。**必ず公式ヘルプで最新を確認してから**出す
- 値付けの最終決定は**ユーザーがする**

> 価格は◯◯円でよいですか？（理由：…）

決まった値段は、工程9で `article.md` の `price:` に**数字だけ**で書く。入稿の最後に、道具が「販売価格」として画面に出す。

### 7. 無料パートを書く

`references/muryo-part.md` と honnin-kata の工程2に従って書く。

- 置くのは**4つだけ**（悩みの言語化／全体像／結論／予告）
- **結論は隠さない。手順は出さない**
- 「得られること／扱わないこと」を並べて書く
- 有料ライン直前の1行で、続きが何かを具体的に書く
- 書き終えたら読み返す。**「で、どうやるの？」で終わっていればOK。すっきり終わっていたら切る位置が後ろすぎる**

### 8. 画像を作る

**最初に道具があるか確認する。**

```bash
which codex || echo "codexなし"
```

`codex` が無ければ、**見出し画像と人物イラストは作れない。図解はHTMLで作れる。** 同じコマンドを繰り返さず、ここで止まってユーザーに聞く。選択肢を出す。

- Codexなしで図解だけ作る（`yuryo-live-image/SKILL.md` の「Codexなしで図解を作る」）
- 画像は後回しにして、入稿まで先に進める（工程9の「画像を作らずに入稿するとき」に従う）
- Codexを入れてから作る（何を入れるか・影響範囲を説明して承認をもらう）

道具があれば、`yuryo-live-image/SKILL.md` と `yuryo-live-image/references/zukai-style.md` を読んでから作る。配色は `profile.md` の「7. 画像の好み」を見る。

枚数の考え方は `muryo-part.md` と `honbun.md` にある（ここには書かない）。

- **作れるのは4種類**：見出し画像・図解・人物イラスト・操作画面のスクリーンショット
- **サムネイル（見出し画像）は必ず1枚**
- 本文の `［図：〜］` を**上から順に1枚ずつ**作り、できたらその場で `![説明](./images/…)` に差し替える
- **始める前に、枚数と時間の目安を1行で伝える**（1枚あたり2〜3分）。確認は求めない。「減らして」と言われたら従う
- 1枚できるたびに進み具合を伝える（`yuryo-live-image/SKILL.md` の「途中経過を伝える」）
- 作った画像は**必ずReadで目視**し、日本語の崩れ・余計な文字・見切れ・色を確認する
- 失敗しても同じコマンドを繰り返さない。原因を確認して次の手をユーザーに聞く
- **数字を見せる図は、本物の数字を指示文に全部書いてから作る。** 書かずに作らせると、AIがそれらしい数字を作る

### 8-2. 操作画面のスクリーンショットを撮る（該当する記事だけ）

有料noteは手順の再現性が価値そのもの。**文章5行より画像1枚のほうが伝わる。**

- 撮り方は `yuryo-live-image/SKILL.md` の「3. 操作画面のスクリーンショットを撮る」に従う
- **ログインが必要な画面では、IDやパスワードを入力しない。** ログインが要るときはここで止まり、ユーザーにログインを頼む
- 撮ったら必ず目視し、メールアドレス・鍵・他人の名前・課金情報が写っていないか確認する。写っていたら貼らない

### 9. 記事フォルダに書き出す

`~/yuryo-kit-live/note-draft/articles/<slug>/` を作る（`<slug>` は英小文字とハイフン。既存フォルダと被らせない）。

`article.md` の形：

```markdown
---
title: 決定したタイトル
price: 決定した値段（数字だけ）
thumbnail: ./thumbnail.png
tags:
  - （商品に合ったタグを3〜5個）
---

（無料パート）

（有料パート）
```

`price:` には工程6で決まった値段を**数字だけ**で書く（例：`price: 1280`）。書かないと、入稿の最後に値段が出ない。

**有料ラインの目印を1行入れる。**

```markdown
（無料パート）

<!-- ここから有料 -->

（有料パート）
```

この行は、記事フォルダの中で位置を示すためのものです。**入稿ツールが自動で取り除くので、note側の本文には入りません。**

ただし、**note側の有料ライン設定そのものは自動化されません。** 入稿後に、この位置で手動で設定する必要があります。

**画像を作らずに入稿するときは、後始末を必ずやる。**

- 本文の `［図：〜］` マーカーは**すべて削除する**。残すと入稿前の検査で止まる
- frontmatter の `thumbnail:` の行を**消す**。存在しないファイルを指すと下見で警告が出る
- 削除した図の枚数と位置は、報告で伝える（あとで差し替えられるように）

**URLはmarkdownリンクで書かない。**

入稿ツールは `[テキスト](URL)` を**テキストだけに変換し、URLを落とす**。Instagram・LINE・関連記事など、URLを読者に渡したいものは、**すべて文章と同じ行に生のURLで置く**。

```
アカウントはこちらです https://www.instagram.com/（あなたのID）
```

**URLだけの行にもしない**（noteがリンクカードに変えるため）。文章と同じ行に置く。

その他：

- 画像は本文の該当見出しの直後に `![](./images/…)` で入れる
- 対応形式は `.png` `.jpg` `.jpeg` `.webp` のみ
- 書き出したら `npm run dry-run -- articles/<フォルダ名>` で下見する。警告の内容を報告に含める

### 10. noteに下書きを入れる（**ここで止まる**）

記事フォルダに書き出したら聞く。

> noteにも下書きを入れますか？（有料設定と価格入力、公開は手動です）

OKが出たら入稿ツールで下書きを作る。

```bash
cd ~/yuryo-kit-live/note-draft && npm run dry-run -- articles/<slug>
cd ~/yuryo-kit-live/note-draft && npm run draft -- articles/<slug> --headed
```

先に `dry-run` で下見し、警告の内容を伝えてから `draft` を実行する。

入稿が終わると、道具が「ここから先は、あなたの手で設定してください」と4行出す（有料ラインの位置／販売価格／返金申請の設定／タグ）。**その内容をそのまま伝える。暗記して言い直さない。**

あわせて、**有料設定・価格入力・販売開始は人が手で行うこと**を伝える。

### 11. 報告する

日本語で簡潔に。絵文字は使わない。

- 無料パートと有料パートの文字数（空白除去後）
- 決まった価格と、有料ラインを引く位置
- 作った画像の枚数
- 記事フォルダのパス
- 手作業で残っていること（有料設定・価格入力・公開）

## 注意

- **構成の承認・材料集め・価格の確定・note入稿では必ず止まる**
- **白紙から本文を書かない。** 材料が無い章は止めて聞く（honnin-kata 工程5）
- **無料パートは有料パートのあとに書く**（honnin-kata 工程2）
- **noteの有料設定・価格入力・公開ボタンは押さない。** ここは人が手で行う
- **URLは文章と同じ行に生で置く。** URLだけの行にすると、noteがリンクカードに変える
- **お金を受け取る記事なので、事実の裏取りは無料noteより厳しくやる。** 数字・料金・仕様は必ず一次情報で確認し、「◯年◯月時点」を添える
- 煽り（今だけ／限定／絶対／やらないと損／人生変わる）は入れない
- 収益・成果の断定をしない（景表法）
- 買わない人を悪く言わない
- 他人の有料noteの中身を写さない。型は参考にしても言葉は独自にする
- **60点で出す**（honnin-kata 工程7）。完璧を目指して止めない
- **このキットは有料note専用。** 無料で配る記事や、クライアント案件の記事には使わない（型が違うので、そのまま使うと合わない）
