# 有料noteの構成を作る

**型の正は `honnin-kata.md` の工程1〜4。** この文書はその実行手順。食い違ったら honnin-kata を優先する。

読者・価格帯・約束・有料ラインの位置・章数・文字数の上限・締めの誘導先（「5. 記事の最後に何をすすめるか」）は**`profile.md` から読む**。

## 役割

**買う前に読まれる無料パート**と、**買った人が読む有料パート**を、1本の記事として設計する。

無料noteの構成と決定的に違う点。

| | 無料note | 有料note |
|---|---|---|
| 冒頭の役割 | 読ませる | **買う理由を作る（誇大なしで）** |
| 中盤の役割 | 理解させる | **実行させる** |
| 締めの役割 | 次のCTAへ | **今日やること1つ → 次のCTAへ** |
| 失敗したとき | 読まれない | **お金を払った人を裏切る** |

## 最初に決める3つ（工程1）

構成に入る前に、この3つが決まっていること。企画シートから引く。

- 読む人（1人に絞る）
- 読み終わった人ができるようになること
- **どこまで無料で、どこから有料にするか**

**3つ目を先に決める。書きながら決めない。** 境界が決まっていないと、無料パートも有料パートも役割が定まらない。

## 完成の定義（ここで決める）

**`profile.md` の「6-2. 記事の長さ」を見る。** そこに書かれた数字を使う。

- 無料パートの文字数
- 有料パートの文字数
- **章の数**（決めたら増やさない）
- **1章あたりの文字数の上限**

**上限で決める。下限にしない。** 下限だと足りない気がして書き足し続ける。上限なら「どれを削るか」を考えることになり、そのほうが記事は良くなる。

profile.mdの目安を使う。

## 全体の骨格

```
【無料パート】※書くのは有料パートのあと
  0. タイトル
  1. 悩みの言語化（いちばん大事）
  2. 全体像（工程がいくつあるか）
  ＋ 得られること／扱わないこと
  3. 結論（答えそのもの。隠さない。手順は出さない）
  4. この先の予告（目次を見せてよい）
  ── 有料ライン ──
【有料パート】※先に書く
  5. 買った直後の1画面（最初の1つを即渡す）
  6. 本編の章（読む人の作業順に並べる）
  7. 今日やること（1つ）
  8. 1人だと止まりやすい場所 → 締めの誘導（誘導先があるときだけ）
```

無料パートは4つだけ。**盛らない。**

## 有料ラインをどこで引くか

**構成工程でいちばん重要な判断。**

**「分かった」の直後、「やってみよう」の直前。**

読んだ人の頭が「なるほど、そうすればいいのか」で止まっている場所。そこから先の「で、具体的にどうやるのか」が有料パート。

**判定のしかた：** 無料パートだけを読み返して、「で、どうやるの？」と自分で思えたら、そこが切り位置。**すっきり終わってしまったら後ろすぎる。**

やってはいけない2つ：

- **全部隠す**（もったいぶると、有料ラインまでたどり着く人が減る）
- **手順まで全部出す**（答えは出していい。手順を出すと買う理由が消える）

profile.md に「有料ラインの位置」の指定があれば、そちらに従う。

## 章の順番

**自分が理解した順ではなく、読む人の作業順に並べる。**

- 1章に2つ入れない
- 順番が合っているかは、上から実行できるかで確かめる
- 章順を入れ替えても成立するなら、作業順になっていない

## 見出しルール

### H2（章タイトル）

読者が得る結果を書く。工程で進む記事なら「工程◯｜〜」の形も使える。

良い例：

- 工程2｜無料パートは「買う理由」を作る場所
- 最初の1件を出すまでにやることは3つだけ
- 僕がここで3ヶ月止まったので先に共有します

悪い例：

- はじめに／基礎知識／◯◯とは／まとめ

### H3（サブ見出し）

**疑問形を主体にする。** 各章2〜4個。

良い例（疑問形）：

- 有料ラインは、どこで切るのか
- 任せていいのは、どこまでか
- 質問は、来る前に潰せますか

良い例（断定形・失敗談と結論に使う）：

- もったいぶった無料パートは、最後まで読まれませんでした
- 1章の中身は、5つのブロックでできています

全部を疑問形にしない。疑問形と断定形を混ぜる。

### 型ラベル

各章に必ず付ける。

- 【無料パート】
- 【有料パート】

## 各章に入れるもの（5ブロック）

有料パートの各章は、この5つで設計する。

1. なぜこれをやるのか
2. **手順**（章の半分くらい。いちばん厚い）
3. 具体例（実際の画面・文面・数字）
4. つまずく場所
5. この章のゴール（「今日のゴール：〜」で締める）

## 必ず入れる要素（有料パート全体で最低6個）

- 手順（番号つき・具体動作まで）
- そのままコピーして使える指示文やテンプレ
- 判断の基準（数字つき）
- チェックリスト
- よくある失敗と回避法
- 実際の画面またはビフォーアフター
- 今日やること
- 1人だと止まりやすい場所（誘導先があるときだけ）

## 期待を合わせる要素

構成の段階で場所を決めておく。

- **得られること／扱わないこと**（無料パートの2の直後）
- **今日やること1つ**（有料パートの締め）

この2つが低評価と返金をいちばん減らす。

## 誘導（有料パートの締め）

profile.md の「5. 記事の最後に何をすすめるか」に従う。

順番：お礼 → 今日やること → **1人だと止まりやすい場所（3〜5個）** → 誘導。

止まりやすい場所を並べてから誘導すると、売り込みにならずに引ける。

**誘導先が「なし」なら、お礼 → 今日やることで締める。** 止まりやすい場所の一覧も置かない（行き先が無いまま、不安だけを残すことになる）。

## 禁止事項

- 前置きだけで有料ラインを引く
- 無料パートで結論を隠す
- 無料パートで手順まで出す
- 調べれば出る情報だけで章を埋める
- 「続きはこちら」だけの目次予告
- 買わない人を責める書き方
- 収益額の約束

## 自己レビュー（出力前に確認）

**買う理由**

- 無料パートに4つ（悩みの言語化／全体像／結論／予告）が揃っているか
- 結論を隠していないか。手順を出していないか
- 読み返して「で、どうやるの？」と思えるか

**買ったあと**

- 有料パート最初の1画面で「よかった」と思えるか
- 各章が5ブロックで設計されているか
- 章が読む人の作業順に並んでいるか
- 現物が6個以上あるか

**期待合わせ**

- 得られること／扱わないことの場所が決まっているか
- 締めが「今日やること1つ」になっているか

## 出力形式

```
タイトル案：…（2〜3個）
想定価格帯：…
有料ラインの位置：「（直前の見出し）」の直後
完成の定義：全◯章／1章あたり上限◯◯字

## 第1章 H2タイトル【無料パート】
### H3タイトル（疑問形）
### H3タイトル

── ここで有料ライン ──

## 第X章 H2タイトル【有料パート】
### H3タイトル
### H3タイトル

無料パート想定文字数：◯◯字（上限）
有料パート想定文字数：◯◯字（上限）
```

## 出力後に必ず添える

- **この有料noteの狙い**（3行）
- **買う理由**（読者がお金を払う決め手・3行）
- **有料ラインをそこで切る理由**（2行）
- **無料パートだけ読んだ人が持ち帰れるもの**（1〜2行）

## この工程の心構え

読者はお金を払う。払う前に不安になり、払ったあとに答え合わせをする。

売るための構成ではなく、**買ってよかったと言われる構成**を作る。
