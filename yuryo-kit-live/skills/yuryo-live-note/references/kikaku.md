# 有料noteの商品企画を固める

**型の正は `honnin-kata.md` の工程1。** 書き始める前に、3つだけ決める。

構成に入る前の工程。**誰の・何を・どこから有料か**を1枚に固める。

ここが曖昧なまま構成へ進むと、あとで全部やり直しになる。急がない。

## 役割

「書きたいこと」ではなく「買われるもの」を決める。

有料noteが売れない理由は、ほぼこの3つのどれか。

- 誰に向けたものか分からない（全員向け＝誰にも刺さらない）
- 無料で手に入る情報しか入っていない
- 買ったあとに何ができるようになるかが見えない

企画工程で潰すのはこの3つ。

## 最初に確認すること（不足時のみ・最大3問）

profile.mdと、ユーザーの発言から埋まらないものだけ聞く。

**あわせて profile.md の「9. あなたらしさを深める」を見る。** 空欄なら飛ばす。

| 書いてあれば | 企画にどう使うか |
|---|---|
| 読者からよく聞かれる質問 | **そのまま章の候補にする。** すでに需要が確かめられている |

1. **売るネタ**（何を教えるnoteか）
2. **書ける実体験・実績**（自分が実際にやったこと・数字・失敗）
3. **想定価格帯**（profile.md にあれば聞かない）

これ以外は聞かずに自分で仮を置き、企画シートに「仮」と書いて出す。

## 0. 先に既存記事との被りを確認する（ネタ候補を出す前に）

**ここを飛ばすと、価格まで決めたあとにやり直しになる。**

1. 記事フォルダ（`<作業ディレクトリ>/articles/`）の**見出しまで見る**。タイトルだけでは何が書かれているか分からない

```bash
grep -n '^## ' <作業ディレクトリ>/articles/<フォルダ>/article.md
```

2. 近いテーマの記事があれば、**どこまで書かれているか**を画面に出す

そのうえでネタ候補を出す。かぶっていたら、有料側は「さらに一段深い実践」に寄せるか、ネタごと変える。**無料記事の焼き直しを売らない。**

## 企画シート（この形で埋める）

### ① 読者（1人に絞る）

profile.mdの読者をさらに**1人まで絞る**。

悪い例：AI副業に興味がある人
良い例：ChatGPTは触ったことがあるけど、それで1円も稼げていない会社員

絞るときに使う軸：

- いまどこで詰まっているか（入口／続かない／単価が上がらない）
- 何を試して失敗したか
- お金を払ってでも飛ばしたい手間は何か

### ② 約束（買うと何が手に入るか）

**行動が変わる形**で1行にする。知識が増える、では弱い。

悪い例：AI副業の全体像がわかります
良い例：この記事を上から実行すると、今週中に1件目の応募文を出せます

約束は**必ず記事の中で回収する**。回収できない約束は書かない。

### ③ どこまで無料で、どこから有料にするか

**本人の型でいちばん重要な3つ目。書きながら決めない。**

原則：**答えは無料で渡す。手順を有料にする。**

- 無料で渡す：悩みの言語化／全体像（工程がいくつあるか）／**結論そのもの**／有料パートの予告
- 有料で渡す：具体的な手順／指示文の全文／判断基準の数字／失敗例／実際の画面

境界が決まっていないと、無料パートも有料パートも役割が定まらない。

やってはいけない2つ：

- **全部隠す**（もったいぶると、有料ラインまでたどり着く人が減る）
- **手順まで出す**（買う理由が消える）

### ③-2 扱わないこと（ここで下書きしておく）

低評価と返金をいちばん減らす要素。企画の段階で3行書いておくと、あとで冒頭に置ける。

- （別の記事で扱うもの）
- （範囲外のもの）
- （この記事では触れないもの）

### ④ 中身の柱（3〜5本）

読者が持ち帰る「できるようになること」を柱にする。章タイトルの元になる。

各柱に、渡す**現物**を1つ以上ぶら下げる。

- 手順（番号つき）
- そのままコピーして使える指示文
- 判断の基準（数字つき）
- チェックリスト
- 失敗例と回避法
- 実際の画面

現物がぶら下がらない柱は、有料の中身にならない。落とすか作り直す。

### ⑤ 完成の定義

**書き始める前に決める。**（honnin-kata 工程7）

- 章の数（決めたら増やさない）
- 1章あたりの文字数の**上限**

**上限で決める。下限にしない。** 下限だと足りない気がして書き足し続ける。上限なら「どれを削るか」を考えることになり、そのほうが記事は良くなる。

### ⑥ 価格帯

profile.md の価格帯を見る。決定は価格の工程（`hanbai.md`）でやるので、ここでは帯だけ置く。

### ⑦ 購入者特典（あれば）

profile.md を見る。特典を付けるなら、**受け取り方まで**決めておく（記事末尾のリンク・LINEで合言葉など）。

## 出力形式

```
## 企画シート

**読む人**：（1人に絞った像）
**できるようになること**：（行動が変わる1行）
**無料と有料の境界**：無料は（〜まで）／有料は（〜から）

**扱わないこと**（下書き）
- （3行）

**中身の柱**
1. （柱）／渡す現物：（手順・指示文・基準・チェックリスト・画面）
2. …
3. …

**完成の定義**：全◯章／1章あたり上限◯◯字
**価格帯**：（profile.mdより）
**購入者特典**：（あれば。受け取り方まで）
**既存の無料記事との差**：（1〜2行）
```

出力したら、承認は求めずそのまま構成工程へ進む。

## 禁止事項

- 全員向けにする（読者を絞らない）
- 無料と有料の境界を決めずに書き始める
- 実体験がゼロのネタで作る（借り物のノウハウを売らない）
- 無料記事の焼き直しを有料にする
- 「これを読めば人生が変わる」系の約束
- 収益額を約束に使う（「月5万稼げます」）。使うなら「目指す」「僕の場合は」に変える

## この工程の心構え

売り手ではなく、**買う側の目**で見る。

自分が1,000円払うとして、この企画に払うか。払わないなら、何が足りないかを言語化してから次へ進む。
