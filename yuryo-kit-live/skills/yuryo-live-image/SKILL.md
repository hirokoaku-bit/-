# yuryo-live-image — note挿入画像を作る

note記事に差し込む画像を作るスキル。作るのは4種類。

**配色と好みは人によって変わる。** 作り始める前に `~/yuryo-kit-live/profile.md` を読み、次に従う。

- 「7. 画像の好み」の「色」— アクセント・文字・背景・補足の色はここから引く
- 「7. 画像の好み」— サムネイルの型（A・B・C）、人物イラストの有無、**入れたくないもの**、Codexを入れたかどうか
- 「6-4. 使ってはいけない表現」— **画像にも出さない**（文字にも、絵にも）

> **「Codexを入れたか」が「入れていない」なら、作れないのはサムネイルと人物イラストの2つだけ。**
> **図解は作れる。** 下の「Codexなしで図解を作る」の手順（HTMLで作る）に進むこと。図解を飛ばしてはいけない。
> サムネイルは本人に用意してもらう旨を伝える。毎回聞き直さない。
> **「入れたくないもの」は毎回守る。** プロンプトに「◯◯は描かない」と明記する。

| 種類 | 作り方 | 使いどころ |
|---|---|---|
| サムネイル（見出し画像） | Codexの `/imagegen`（Image 2.0） | 一覧で目を止めてもらう。記事に1枚 |
| 図解スライド | Codexの `/imagegen`（Image 2.0）。**Codexが無ければHTMLで作る**（下の「Codexなしで図解を作る」） | 比較・手順・考え方の整理 |
| 人物イラスト | Codexの `/imagegen`（Image 2.0） | 記事の空気をやわらげる、アイキャッチ |
| 操作画面 | 実際の画面を撮り、赤枠と注釈を重ねる | 登録方法・操作手順など「見せたほうが早い」箇所 |

> **このキット（ライブ版）で作らないもの**：カード型・表の画像・Before/After・ワークシート・手順の連結図・実績の画面・毎回入れるバナー。
> 頼まれたら「このキットには入っていない画像です」と伝え、上の4種類で代わりになるもの（比べる図なら図解の「比較2カラム」、手順なら操作画面を1枚ずつ）を提案する。

## 参照

- `~/yuryo-kit-live/profile.md` の「7. 画像の好み」 — **配色・型・入れたくないものはここから引く。作る前に必ず読む**
- `~/yuryo-kit-live/profile.md` の「9. あなたらしさを深める」の顔出し欄 — **「使わない」なら、本人の写真を使う案は出さない**
- `references/thumbnail-style.md` — サムネイルの型（A・B・C）。**サムネイルを作る前に必ず読む**
- `references/zukai-style.md` — 図解のレイアウトの型。**図解を作る前に必ず読む**
- `references/design-system.md` — HTML/CSSで作る旧デザイン。Codexなしで図解を作るときだけ使う
- `assets/figure-template.html` — HTMLで図解を作るときのひな形

> **図解は「素っ気なくしない」のが肝。** クリーム色の背景・四隅の装飾・カードの影・まとめ帯の4つを毎回入れる。
> 「フラットでミニマル」「影なし」「装飾なし」と書くと必ず貧相になる。詳しくは `zukai-style.md`。

## 0. どの道具で作るか（最初に1回だけ確認）

**まず `profile.md` の「7. 画像の好み」の「Codexを入れたか」を見る。**

- 「入れていない」と書いてある → 下の分岐は**聞かない**。そのまま「Codexなしで図解を作る」へ進む
- 「入れた」と書いてある → Codexで作る
- 空欄のときだけ、次を実行して確かめる

```bash
codex --version
```

| 結果 | どう進めるか |
|---|---|
| 番号が出る | **Codexで作る。** 下の「サムネイル」「図解スライド」などの手順をそのまま進める |
| 「command not found」と出る | Codexが入っていない。下の分岐へ |

**Codexが入っていないときは、ユーザーにこう伝えて選んでもらう。**

> 画像づくりには2つの選び方があります。
> **A：Codexを入れる**（おすすめ）— ChatGPTの有料プラン（月20ドル〜）が必要ですが、追加料金なしで、サムネイルもイラストも作れます。導入は1コマンドで数分です。
> **B：入れずに進む** — 記事中の図解だけを作ります。追加料金はかかりません。サムネイルと人物イラストは作れないので、ご自身で用意していただく形になります。

Aを選ばれたら、この1行を案内する（実行はユーザー本人に任せてよい）。

```bash
npm install -g @openai/codex
```

入れたあと、初回だけ `codex` と打ってChatGPTアカウントでログインしてもらう。**ログイン情報を代わりに入力してはいけない。**

Bを選ばれたら、この下の「Codexなしで図解を作る」に進む。

## 色の決め方（サムネイルと図解で背景だけ変える）

アクセント色・主文字色・補足色は、`profile.md` の値を**全部の画像で共通**に使う。
**背景だけは用途で変える。** これは意図的な使い分けなので、揃えないこと。

| | 背景 | なぜ |
|---|---|---|
| サムネイル | **ほぼ白**（極薄いクリーム） | noteの記事一覧では他の記事と横に並ぶ。白のほうが文字が立って目に留まる |
| 挿入図解 | **クリーム** `#FDF8F0` | 記事の本文は白地。図をクリームにすると「ここは図」と面で区切れて読みやすい |

`profile.md` の「背景の色」に記入があるときは、**図解側の背景**として使う。
サムネイルはそれより一段明るい色（ほぼ白）にする。

## 共通：Codexの呼び出し方

作業ディレクトリは `~/yuryo-kit-live/note-draft`。

```bash
cd ~/yuryo-kit-live/note-draft
echo "[3/7] 開始 $(date +%H:%M)"; codex exec --skip-git-repo-check "<プロンプト>" < /dev/null; echo "[3/7] 完了 $(date +%H:%M)"
```

> **`echo` の印は必ず付ける。** これがあると、あなたが報告を忘れても、画面に「何枚目を作っているか」と
> 「いつ始まったか」が残る。`[3/7]` の数字は毎回、実際の枚数に書き換えること。

> **`< /dev/null` は必ず付ける。** これが無いと、Codexはプロンプトを受け取ったあとさらに標準入力を読もうとして、
> 無反応のまま何十分でも固まる。詳しくは下の「無反応で固まったとき」。

> **必ず `~/yuryo-kit-live/note-draft` の中で実行する（ここに `AGENTS.md` を置いてある）。**
> - 作業フォルダに `AGENTS.md` が無いと、「指示書が見つかりません。探してよいですか？」と確認を返して**画像ゼロで終わる**ことがある
> - `-c project_doc_max_bytes=0` で読み込みを切る手もあるが、**AGENTS.md まで無効化されて上の失敗を招く**ので使わない

OpenAIのAPIキーは要らない（ChatGPT側の枠を使うため、1枚あたりの課金なし）。

### 無反応で固まったとき

コマンドを投げたのに何も返ってこないときは、**まずCPU時間を見る**。

```bash
ps -o pid,etime,time -p $(pgrep -f "codex exec" | head -1)
```

- 経過時間が何分もあるのに**CPU時間が0.1秒未満**なら、計算しておらず「何かを待っている」状態
- いちばん多い原因は**標準入力の待ち**。`< /dev/null` を付け忘れている
- 出力を `| tail` に通すと先頭のログが見えず、原因の1行（`Reading additional input from stdin...`）を見逃す。
  詰まったら **`> ログファイル 2>&1` でそのまま落として、1行目から読む**
- `-s workspace-write` の有無は関係ない（付けても外しても同じように固まった）
- **同じコマンドを繰り返さない。** 原因を確かめてから次の手を打つ

### 必ず守ること（検証で分かった落とし穴）

- **1回に1枚だけ**。まとめて作らせない
- **保存は「cp コマンドでコピーするだけ」と書く**。リサイズ・変換・`sips` を頼むと、Codexが失敗して確認待ちで止まる
- **保存先は絶対パスで書く**
- **作り直すときは保存先を別の名前にする**。同じ名前のファイルが既にあると、Codexが上書き確認で止まることがある。止まっても画像は生成済みなので、`~/.codex/generated_images/` の最新を自分でコピーすれば済む
- **サイズは「16:9」「正方形」程度にとどめる**。ピクセル数を厳密に要求すると「指定と違う」と判断して止まる
- 生成元の画像は `~/.codex/generated_images/<セッション>/` にも残る。指定パスに来ていなければここから拾う
- 出来上がったら**必ずReadで開いて目視する**。イメージと違えばプロンプトを直して作り直す

## 途中経過を伝える（必ずやる）

画像づくりは**1枚あたり2〜3分**かかる。7枚なら15〜20分。この間、黙って作り続けると、
相手は「固まったのでは」「失敗したのでは」と不安になる。**何も言わずに2枚以上続けて作らない。**

**1. 始める前に、見通しを1行で伝える**

> これから画像を7枚作ります。1枚あたり2〜3分、全部で15〜20分ほどです。
> 1枚できるたびにお知らせするので、その間は席を立っていただいて大丈夫です。

枚数は「サムネイル1枚＋図解の枚数」。図解の枚数は下の「何枚入れるか」で決める。

**2. 1枚できるたびに、1行だけ報告する**

```
[3/7] 図解「15分で終わる4つの手順」ができました。残り4枚・10分ほどです。
```

- 先頭に `[できた枚数/全体の枚数]` を必ず付ける
- 残り時間は **残り枚数 × 2.5分**で概算してよい
- **長い説明は書かない。1行で足りる**

**3. 作り直すときも黙らない**

```
[3/7] 日本語が崩れていたので、作り直します（もう2〜3分いただきます）
```

**4. 全部終わったら、まとめて1行**

```
画像7枚ができました（サムネイル1枚・図解6枚）。全部で16分でした。
```

> **相手に確認を求めるのではない。** 進み具合を伝えるだけで、返事を待たずに次の1枚へ進む。

## 何枚入れるか（必ず守る）

**ワンスクロールに最低1枚**、画像かスクリーンショットを入れる。

- スマホで1スクロール＝おおよそ**500〜700字**。なので**500字に1枚**を目安にする
- 3,500字の記事なら**7〜8枚**。「見出しごとに1枚」だと足りないことが多い
- 画像なしで1,000字以上続く箇所を作らない。書き上げたら本文を上から見て、**画像と画像の間隔**を必ず確認する
- サムネイル（見出し画像）はこの枚数に含めない。別で1枚作る

足りないときの埋め方（本文を増やさずに済む）。

- 「今までのやり方／新しいやり方」を並べた図解（比較2カラム）
- 数字だけを大きく見せる1枚
- その章のまとめをチェックリストにした1枚
- 実際の操作画面のスクリーンショット

## 0. サムネイル（見出し画像）を作る

記事の顔になる1枚。**記事ができたら必ず1枚作る。**

1. `references/thumbnail-style.md` を読み、型を選ぶ
   - 迷ったら**型A（完全ガイド型）**。「5日間で」「3ステップで」の形なら型B、特典つきなら型C
2. 記事のタイトルから、画像に出す文字を決める。**メインコピーは25文字以内**。3段に割り、真ん中の段を主役にする
3. `thumbnail-style.md` のプロンプトのひな形に、選んだ型の説明を**要約せずそのまま書き写して**Codexを呼ぶ
4. できた画像をReadで開いて確認する

> **効くのは細部の指定。** 次の4つを省くと途端に素人っぽくなる。
> 助詞（を・に・で）だけ一回り小さく／タイトルの下に帯を1本／ノートパソコンは画面の中のUIまで描く／大きさや個数の数値をそのまま書く

> **サムネイルは記事フォルダの直下に `thumbnail.png` として置く。** `images/` の中ではない。
> あわせて `article.md` の先頭に `thumbnail: ./thumbnail.png` の1行を入れる。

## 1. 図解スライドを作る

### 手順

**先に `profile.md` の「Codexを入れたか」を見る。「入れていない」なら、この節は飛ばして「Codexなしで図解を作る」へ。**

1. `references/zukai-style.md` を読む
2. 記事を読み、どの見出しの後に・どの型（比較2カラム／3ステップ／チェックリスト等）を置くか決める
3. 下のひな形に当てはめてCodexを呼ぶ
4. できた画像をReadで開いて確認する

### プロンプトのひな形

```
/imagegen で画像を1枚だけ作って。サイズや品質の細かい確認は不要。生成できたら cp コマンドでコピーするだけにして（sips やリサイズは絶対に使わない）。

【モデル】Codex内蔵の image_gen（gpt-image-2 / Image 2.0）。CLIフォールバックは使わない
【用途】infographic-diagram。日本語のプレゼン図解スライド。16:9
【デザイン】背景は<テーマの背景色>（真っ白にしない）で、四隅に淡い丸い形と小さな装飾。アクセント色は<テーマのアクセント色>。文字は<テーマの主文字色>、補足は<テーマの補足色>。太いゴシック体（日本語）。カードは白地・角を大きく丸め・やわらかい影。下にまとめ帯（電球アイコン＋「ポイント」＋黄色いマーカー線）。写真的表現なし
【レイアウト】
（zukai-style.md の型から1つ選び、要素の位置・枠の色・アイコンまで具体的に書く）
【文字】日本語はすべて正確に、崩れずに描くこと。次の文言を一字一句そのまま描く：
（画像に出す文言を全部そのまま列挙する。要約させない）
【禁止】ウォーターマーク、指定外の文字、絵文字、崩れた日本語（profile.md の「入れたくないもの」があれば、ここにそのまま書き足す）
【保存】cp で <保存先の絶対パス> へコピーする
【報告】モデル名と保存先パスの1行だけ
```

> **数字を見せる図は、本物の数字を【レイアウト】に全部書いてから作る。** 書かずに作らせると、AIがそれらしい数字を作る。

## 2. 人物イラストを作る

図解と同じ呼び方で、中身だけ差し替える。

```
【用途】illustration-story。人物イラスト。正方形
【内容】<英語で描写>。soft flat clean line-art, thin brown outlines, soft minimal coloring, warm pastel, cream background, no text, no watermark
```

- 画風の指定（`soft flat clean line-art` 以下）は既存記事の人物に合わせたもの。変えない
- 人物は30〜50代の日本人。読者に近い年代にする

### 背景を透過させたいとき

`gpt-image-2` は透過に対応していない。緑一色の背景で作ってから抜く。

1. プロンプトに次を入れる：`on a perfectly flat solid #00ff00 chroma-key background, no shadow, no reflection, no gradient, crisp edges`
2. 生成後に抜く：

```bash
python "$HOME/.codex/skills/.system/imagegen/scripts/remove_chroma_key.py" \
  --input <元画像> --out <出力.png> \
  --auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill
```

3. 抜いたあと、白いフチや緑の残りがないかReadで確認する

## 3. 操作画面のスクリーンショットを撮る

「登録方法」「操作手順」など、**実際の画面を見せたほうが伝わる箇所**で使う。

### Web画面（登録ページ、管理画面など）

**専用スクリプトで撮る。**

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/shot-url.mjs "<URL>" articles/<記事>/images/<名前>.png 1280 760
```

- 第5引数に `full` を付けるとページ全体、省略すると画面に見えている範囲だけ
- `deviceScaleFactor:2` で撮るので、実ファイルは指定の2倍解像度（1280×760 なら 2560×1520）

> **ブラウザツール（`mcp__Claude_Browser__`）で撮らないこと。**
> 見て確認するだけなら使えるが、**画像がファイルとして保存されない**ので記事に差し込めない。
> 解像度も 800×450 に落ちる。

### Macのアプリ画面（Claude Code、Notionアプリなど）

```bash
screencapture -x <保存先の絶対パス>.png
```

- `-x` はシャッター音を消す
- 画面の一部だけ撮りたいときは `-i`（ユーザーがマウスで範囲を選ぶ）
- 撮りたい画面を**先に前面に出しておく**必要がある。出ていなければユーザーに頼む

### Windowsのアプリ画面

**`screencapture` は使えない。あなた（AI）が撮ることはできないので、ユーザーに撮ってもらう。**

> 撮りたい画面を前に出して、`Windows` キーと `PrintScreen` を同時に押してください。
> `ピクチャ\スクリーンショット` に自動で保存されます。保存された場所を教えてください。

- 受け取ったファイルを記事の `images/` へコピーして使う
- 範囲を選んで撮りたいときは `Windows` ＋ `Shift` ＋ `S`（クリップボードに入るので、ペイント等で保存してもらう）
- **Webページの画面なら、この手順は不要。** `shot-url.mjs` で自分で撮れる

### 撮った画面に注釈を入れる

「ここを押す」「この欄に入れる」を示すときは、**赤い枠とラベル**を重ねる。撮ったあとに別の道具で加工する必要はない。

**枠で囲む**（押す場所・入力欄を指すとき）

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/annotate.mjs <元の画像> <出力先> <幅> <高さ> '[{"x":120,"y":300,"w":420,"h":64,"label":"ここに入力"}]'
```

- `x` `y` は左上からの位置、`w` `h` は枠の大きさ（元画像の実寸で指定する）
- `label` を省くと枠だけになる。ラベルは枠の上に出る
- 枠は複数置ける。JSONの配列に足すだけ

**矢印で指す**（離れた場所から指し示すとき）

同じ `annotate.mjs` に、`arrow` の指定を混ぜる。

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/annotate.mjs <元の画像> <出力先> <幅> <高さ> '[{"x":175,"y":655,"w":625,"h":72},{"arrow":true,"x1":900,"y1":230,"x2":810,"y2":650,"label":"この緑のボタンを押すだけ"}]'
```

- `x1` `y1` が矢印の根元、`x2` `y2` が指す先（先端に矢じりが付く）
- `label` は根元の上に出る。**指す先の近くではなく、根元に付く**
- 枠と矢印は同じ配列に混ぜてよい。上の例は「枠で囲みつつ、離れた位置から矢印で指す」形

**左の余白にラベルを並べる**（手順1・2・3のように縦に並んだ画面を説明するとき）

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/annotate-side.mjs <元の画像> <出力先> <幅> <高さ> '[{"y":180,"h":90,"label":"1. メールアドレスを入れる"}]' 250
```

- 最後の数字は左に空ける余白の幅（省略すると250）
- **出力は、指定した幅に余白のぶんを足した大きさになる**（1280の画像に余白250なら、出来上がりは1530×高さ）。記事に貼ると少し横長になるので、それでよいか確認する
- `{"box":true,"x":100,"w":400}` を足すと、その範囲を赤枠でも囲む

**注意**

- **色は赤（`#E5252A`）で固定**。`profile.md` の配色には合わせない。注釈は「目立つこと」が役目で、記事の図解とは役割が違う
- `profile.md` の「入れたくないもの」に赤系の指定があるときだけ、ユーザーに確認する
- 位置は一度で決まらない。**作ったら必ずReadで開いて、ずれていたら数値を直して作り直す**
- 元の画像は上書きせず、別名で出力する

### 必ず守ること

- **ログインが必要な画面では、IDやパスワードを入力しない。** ユーザーにログインしてもらってから撮る
- 撮ったら**必ずReadで開いて目視し**、次が写り込んでいないか確認する
  - メールアドレス、電話番号、住所
  - APIキー、トークン、パスワード
  - 他の人の名前、取引先の情報
  - 課金額、口座、カード情報
- 写り込んでいたら、撮り直すか、その部分を隠してから使う。**そのまま記事に貼らない**

## Codexなしで図解を作る（HTMLで作る）

**Codexを入れていない人の図解は、こちらで作る。** 追加の道具は要らない（キットに入っているブラウザ部品だけで動く）。
料金表や正式名称など、**1文字も間違えられない図**も、Codexの有無にかかわらずこちらで作る（文字が確実に正しく出るため）。

見本は `~/yuryo-kit-live/画像の見本` の `挿入図解-Codexなし-流れ.jpg` と `挿入図解-Codexなし-数字.jpg`。

### 手順

1. `references/zukai-style.md` を読んで型を決める（比較2カラム／3ステップ／チェックリスト／数字を大きく など。型はCodexと同じものを使う）
2. `references/design-system.md` を読む
3. `assets/figure-template.html` を作業用にコピーする

```bash
cd ~/yuryo-kit-live/note-draft
cp ../skills/yuryo-live-image/assets/figure-template.html articles/<記事>/fig1.html
```

> **`/tmp` は使わない。** Windowsには無いので、記事フォルダの中に置く。

4. コピーしたHTMLの `<body>` の中身（本体）を、決めた型に差し替える。**色は `profile.md` の「色」の4色に置き換える**（ひな形の初期値はオレンジ系）
5. 画像に変換する。**幅と高さは、HTMLの `html,body{width:...;height:...}` と必ず同じ値にする**

```bash
cd ~/yuryo-kit-live/note-draft
node scripts/render-figure.mjs articles/<記事>/fig1.html articles/<記事>/images/fig1-<名前>.png 1600 900
```

> 中身の高さに合わせて切り出したいときは、最後に `full` を付ける（`... 1600 900 full`）。高さの数え間違いで下のまとめ帯が切れるのを防げる。

6. できた画像をReadで開いて目視する（文字の見切れ・折り返しの崩れ・色）

### つまずきやすいところ

- 文字がカードからはみ出す → フォントを1〜2px下げるか、カードの幅を広げる
- 日本語が変な位置で折り返す → 読点や文節の位置に `<br>` を手で入れる
- 画像が指定より大きい → `deviceScaleFactor:2` で出力しているため。実ファイルが2倍の解像度になるのは正常
- 背景が白いだけで素っ気ない → ひな形の背景グラデーション・カードの枠・下のまとめ帯を消さない（消すと途端に貧相になる）
