# note-draft — noteの下書きを自動で作るツール（有料note作成キット ライブ版同梱）

記事のテキストと画像をフォルダにまとめておくと、コマンド1つで **note.com の「下書き」まで**自動で作ります。
**公開ボタンは自動で押しません。** 最後は必ず、あなたがnoteの画面で確認してから手で公開します。

> なぜ下書きまでか：誤公開・重複投稿・画像抜け・ログイン切れの事故を防ぐためです。

---

## 使うために必要なもの

- Node.js が入ったPC（Mac / Windows。Windowsはベータ対応）
- Google Chrome / Chromium が動くPC
- note のアカウント（自分でログインできること）
- 入稿したい記事フォルダ（`article.md` ＋ 画像）

> Windowsの方は、下のコマンドをPowerShell向けに読み替えてください（`~/yuryo-kit-live` → `$HOME\yuryo-kit-live`）。
> 読み替え例は、キット同梱の `Windows導入ガイド.md` にあります。

（インストール等は導入時に済ませてあります。増やす場合のみ `npm install` します）

---

## いちばん最初に1回だけ：ログイン

```
npm run login
```

- ブラウザが開きます。**あなたが手動で note にログイン**してください。
- ログインを検知すると自動で保存し、ブラウザが閉じます（Enter入力は不要）。
- 「実際にエディタを開けるか」で確認するので、本当にログインできたときだけ保存します。
- パスワードは保存しません。ログイン済みの状態だけを `storage/note-auth.json` に保存します。

一度やれば、しばらくは再ログイン不要です（ログインが切れたら、もう一度これを実行）。

## 記事フォルダの作り方

`articles/` の中に、記事ごとのフォルダを作ります。

```
articles/
  my-article/
    article.md        ← 本文（下記の書き方）
    thumbnail.png     ← サムネイル（見出し画像）／任意
    images/
      fig1.png        ← 本文中に入れる画像
      fig2.png
```

`article.md` の書き方：

```markdown
---
title: 記事のタイトル
price: 1280
thumbnail: ./thumbnail.png
tags:
  - AI
  - 副業
---

本文をふつうに書きます。

![説明](./images/fig1.png)

## 見出し

続きの本文。

![説明](./images/fig2.png)
```

- 画像は `![説明](パス)` と書いた場所に入ります。
- 対応画像：`.png` `.jpg` `.jpeg` `.webp`（`.gif` `.svg` などは非対応）
- **`tags:` は下書きに自動では入りません。** `npm run dry-run` で一覧を表示するので、それを見ながら note の下書き画面で貼ってください。
- **`price:` は note の価格欄には入りません。** 入稿の最後に「販売価格」として画面に出すための値段です。数字だけで書きます。

## 実行の流れ

### 1. 事前チェック（noteには触りません）

```
npm run dry-run -- articles/my-article
```

タイトル・本文文字数・画像の枚数・サムネイルの有無を確認します。ここでエラーが出たら直します。

### 2. 下書きを作る

ふだんは、Claudeに「**入稿して**」と伝えれば、これをClaudeが実行します。自分で打つ場合は次のとおりです。

```
npm run draft -- articles/my-article --headed
```

- **必ず画面ありモード（--headed）で実行してください。** noteのエディタは画面なし(headless)だと読み込めません。
- ブラウザが開いて、noteの新規投稿画面に入力していきます。
- タイトル → サムネイル（見出し画像）→ 本文 → 本文画像 → **下書き保存** の順です。
- 終わると「下書きURL」を表示します。noteの画面で中身を確認してください。

> 注意：`npm run` に渡す引数は `--` を1回だけ付けます（`-- articles/... --headed`）。`-- ... -- --headed` のように `--` を2回付けるとエラーになります。

うまくいかないときは、画面を残して調べられます：

```
npm run draft -- articles/my-article --headed --pause-on-error
```

### 3. 公開

**このツールは公開しません。** note の画面で内容を確認し、問題なければ **あなたが手で公開**してください。

## 画像を作る道具（scripts/）

記事に入れる画像は、ふだんはClaude Codeが自動で使います。手で動かすこともできます。

| スクリプト | 何をするか | 使い方 |
|---|---|---|
| `annotate.mjs` | 画面の画像に**赤い枠・矢印・注釈の文字**を入れる | `node scripts/annotate.mjs <元画像> <保存先> '<注釈のJSON>'` |
| `shot-url.mjs` | Webページを撮る（2倍の解像度） | `node scripts/shot-url.mjs "<URL>" <保存先> 1280 760 [full]` |
| `render-figure.mjs` | HTMLから図解のPNGを作る。**最後に `full` を付けると中身の高さに合わせて切り出す** | `node scripts/render-figure.mjs <html> <保存先> <幅> <高さ> [full]` |
| `annotate-side.mjs` | 画面の画像の**左側にラベルを並べる**（出力は余白のぶん横に広がる：1280＋250＝1530） | `node scripts/annotate-side.mjs <元画像> <保存先> '<ラベルのJSON>'` |
| `verify-full.mjs` | 入稿した下書きの**本文の並びを文字で出す** | `node scripts/verify-full.mjs <下書きURL>` |
| `verify-draft.mjs` | 入稿した下書きの**画面を撮る** | `node scripts/verify-draft.mjs <下書きURL>` |
| `inspect-editor.mjs` | noteのエディタの構造を調べる（**入稿が壊れたときの復旧用**。下の「ツールが壊れたとき」を見る） | `node scripts/inspect-editor.mjs` |

## 出す前の検査（`npm run dry-run`）

noteにアクセスする前に、記事フォルダの中だけで確かめます。**`✗` があると入稿は止まります。**

| 見るもの | 止まるか |
|---|---|
| タイトル・本文・画像・サムネイルがそろっているか | ✗ 止まる |
| リスト行に全角スペースが無いか（あるとnoteのリストが壊れて、以降が全部箇条書きになる） | ✗ 止まる |
| **差し込み待ちの印（`［図：〜］` など）が残っていないか** | ✗ 止まる |
| **書きかけらしき文字（「（ここに〜）」など）が無いか**（コードブロックの中は数えない） | △ 知らせるだけ |
| **メールアドレス・電話番号が混ざっていないか** | △ 知らせるだけ |
| **有料ラインの目印（`<!-- ここから有料 -->`）があるか** | △ 知らせるだけ |
| **無料／有料パートが `profile.md` の文字数の上限に収まっているか** | △ 知らせるだけ |

`annotate.mjs` の注釈は、画像の左上を 0,0 とした座標で指定します。

```bash
node scripts/annotate.mjs shot.png out.png '[{"type":"box","x":1084,"y":10,"w":88,"h":30},{"type":"text","x":880,"y":95,"value":"ここを押す"}]'
```

- `box` … `x` `y` `w` `h` で赤い枠
- `arrow` … `x1` `y1` `x2` `y2` で赤い矢印（`x2,y2` が先端）
- `text` … `x` `y` `value` で赤い太字（白フチつき）

> 見出し画像とイラストそのものは、これらではなく **Codex**（ChatGPTの有料プラン）で作ります。
> 詳しくはキット同梱の `skills/yuryo-live-image/SKILL.md` を見てください。

## このフォルダの `AGENTS.md` について

画像づくりの道具（Codex）が読むファイルです。**消さないでください。**
無いと、画像を作る前に「指示書が見つかりません」と確認を返して、1枚も作らずに終わることがあります。

## 困ったとき

- まず環境を点検： `npm run doctor`
- 失敗時は `screenshots/` に画面が、`logs/` に手順のログが残ります（本文全文やパスワードは記録しません）。
- 「タイトル欄が見つからない」等が出たら、noteの画面が変わった可能性があります。`src/selectors.ts` を直せば直ります（変更箇所はこのファイルに集約しています）。

## 制限（MVPで割り切っていること）

- **画面ありモード必須**：noteエディタはheadlessだと読み込めないため、`--headed` で実行します。
- **インラインコード（`` ` `` で囲んだ語）はプレーン表示になります**：noteに対応する記法が無いため、記号を外して普通の文字で入れます。強調したい語は太字かかぎかっこを使ってください。見出し・太字・箇条書き・番号リスト・コードブロックは再現されます。
- **表（テーブル）は箇条書きに変換して入れます**：note側に表を作る機能が無いためです。`| 項目 | 説明 |` の形で書くと「**項目**：説明」の箇条書きになり、ヘッダ行と区切り行（`|---|---|`）は落とします。3列以上は2列目以降を「 / 」でつなぎます。表の形のまま載せたいときは、画像にして貼ってください。
- **画像は本文中の正しい位置に入ります**：本文をMarkdownのまま上から打ちながら、`![](…)` の行に来たらその場に差し込みます（`--no-inline-images` を付けると末尾にまとめます）。挿入に失敗した画像は末尾に回るので、その場合は下書き画面でドラッグ移動してください。
- **1回実行するごとに新しい下書きが1件作られます**：同じ記事で複数回試すと下書きが増えます。不要なものは note の下書き一覧から手動で削除してください（このツールは削除しません）。
- 自動公開・予約投稿・既存記事の編集/削除・複数アカウント・CAPTCHA/2段階認証の自動突破は**やりません**。

## 画面が変わって動かなくなったら

noteのエディタ更新でボタンや入力欄の場所が変わると失敗することがあります。`src/selectors.ts` に操作対象を集約しているので、そこを直せば復旧できます。実画面の構造を調べる補助スクリプト `scripts/inspect-editor.mjs` で、現在のボタン名やセレクタを確認できます。

詳しい安全方針は [SECURITY.md](./SECURITY.md) を見てください。
